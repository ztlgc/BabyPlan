# BabyPlan APK 发布检查清单

只有在下列项目都有实际证据时才把版本标记为可发布。Debug APK 只能证明构建链路，不能作为正式交付。

当前 `v0.1.3` 已生成持久签名的私人 Release APK，签名、包信息、大小、SHA-256 和证书值均有记录；内容人工审读和真实 Android 设备验收仍阻断正式放行。

## 构建前

- [ ] 内容包通过 v2 结构校验，来源、人工审读和家庭试玩记录齐全。
- [ ] 发布内容没有任何 `candidate` 或 `draft` 被当作已审内容。
- [x] 当前源码的 Release 同时支持 HTTP 与 HTTPS，服务地址由用户填写；历史 v0.1.3 包仍仅接受 HTTPS。HTTP 仅限可信局域网，未把管理员或测试地址打进正式包。
- [x] `flutter analyze`、90 项 Flutter 测试、2 项 Android 原生规则测试、`npm run typecheck`、API 测试、`npm run build` 和 26 项网页测试通过。
- [x] 两份手机 SQLite 经真实 Fastify/PostgreSQL 同步，覆盖测量与阶段观察的更正、删除、回收和恢复。
- [x] 服务端 `/health/ready` 通过，0001～0010 迁移已在隔离 PostgreSQL 9.5.4 实际应用。
- [x] 开发环境数据库和媒体备份已生成并完成恢复演练。

## 签名与产物

- [x] 持久签名私钥位于被 Git 忽略的 `private/android-signing/`，仅通过本地 `key.properties` 提供给构建。
- [x] `applicationId` 固定为 `app.babyplan.babyplan`。
- [x] 本次 `versionCode=4`、`versionName=0.1.3`，沿用 0.1.0 以来的持久签名。Debug 包名与私人 Release 不同。
- [x] 使用持久 release 签名构建，不使用 debug key。
- [x] 用 `apksigner verify --verbose --print-certs` 验证 APK Signature Scheme v2 和证书 SHA-256。
- [x] 已在 `manifest.json`、`release-badging.txt` 和 `SHA256SUMS.txt` 记录路径、字节数、SHA-256 和证书摘要。
- [ ] 在全新安装设备上升级到新版本，确认数据迁移和登录会话行为符合预期。

## 真机验收

- [ ] 浅色、深色、200% 字号、窄屏、横屏和 TalkBack 基本路径可用。
- [ ] 登录、刷新、退出和重启后凭据行为正确，令牌不出现在 SQLite 或日志。
- [ ] 飞行模式保存参与和成长记录，杀进程后重开仍存在，联网后成功同步。
- [ ] 两位家长读取同一家庭；另一家庭访问返回 404；重复 operationId 不重复写入。
- [ ] 通知首次启用才申请权限；拒绝后核心功能仍可用。
- [ ] 通知在锁屏、省电、重启、改时间和应用升级后的实际送达/延迟符合说明。
- [ ] 20 点后没有补发过期提醒；关闭提醒或登出后不再提醒。
- [ ] 照片选择授权、取消、失败重试、重启恢复、跨家庭隔离和删除墓碑完成验收。
- [ ] A4 打印、导出下载、过期链接和遗漏媒体清单完成验收。

## 交付记录

- [ ] 记录执行环境、设备型号、Android 版本、服务器版本和测试日期。
- [ ] 分开列出“自动化通过”“真机通过”“真实服务器通过”和“未执行”。
- [ ] 不把模拟器、静态原型、接口合同或 Debug 构建冒充正式 Android 验收。
- [ ] 发布包不包含真实家庭资料、数据库备份、管理员凭证或测试账号口令。

## 当前结论

- 私人技术产物：已构建，签名和哈希已核验。
- 局域网开发试用：已构建 Debug APK，仍需真实手机连接局域网服务。
- 公开/长期正式发布：**未放行**。候选内容人工审读、真实设备、双机同步、覆盖升级和公网 HTTPS 均未完成。
