# 服务端设计简报

> 范围标识（2026-11-11）：本文对应现有v0.1合同，仍用于旧流程实现对照。扩展需求已包含成员协作、每日多项、媒体和内容管理；新原型读取 [原型范围与三端简报](05-原型范围与三端简报.md)，不能用本合同承载新对象。本文“不增加管理后台”等限制仅适用于旧基线，未将新需求归档或取消。

版本 v0.1；2026-11-11。技术方案：Fastify + TypeScript + PostgreSQL，面向一个家庭、一台 Flutter 安卓手机。

## 1. 本任务交付什么

设计服务端架构、数据模型、API交互和故障恢复。成果应能帮助开发者实现，不把架构图当作已运行的服务。

首版不增加 Web 管理后台。内容导入、激活和回滚以受控运维工具处理；无公开注册、CMS、课程管理或分析仪表盘。若以网页交付，网页用于阅读技术设计。

## 2. 服务职责

1. 校验并保存有版本的内容包；独立维护当前激活版本，导入失败保持原版本。
2. 按家庭时区、模板和开始日生成七天计划，每天一张卡，保存当时完整快照。
3. 处理家庭凭证、记录归属、打卡当前结果、操作重放和修订冲突。
4. 按任务日期计算基础周报；未来日期不计未记录。
5. M4 再加入可失败的建议模块；只消费最少结构化数据，家长确认后才影响下周。

手机负责本地月龄、提醒时间与开关、SQLite 缓存和待同步队列；服务端不代发安卓本地通知，也不接收姓名、生日或照片。

## 3. 必须说明的视角

| 视角 | 必须包含 |
| --- | --- |
| 系统边界 | Flutter、SQLite、安卓通知、家庭API、PostgreSQL、受控内容导入；M4模型模块单独标注 |
| 数据关系 | 家庭、内容版本、激活指针、周计划、任务快照、当前打卡、操作幂等记录 |
| 创建周计划 | 鉴权与归属、幂等重放、活跃版本检查、起始日期检查、事务、日期唯一约束、快照 |
| 修改打卡 | operationId重放优先、baseRevision核对、状态反馈配对、修订递增、响应丢失后恢复 |
| 离线同步 | 同任务串行、本机新编辑、旧响应、版本冲突的用户确认；不声称离线自动建新周 |
| 内容发布 | Schema和业务校验、同版本同内容重入、异内容拒绝、原子激活、回滚不改历史 |
| 基础回顾 | 周时区的今天、四种统计状态、recordsVersion、日期推进导致快照失效 |
| 运维 | 配置边界、HTTP/HTTPS与私人访问、健康检查、日志不含凭证、备份恢复步骤 |

无需引入微服务、消息队列、分布式缓存或独立内容后台。使用单体服务和数据库事务即可覆盖当前范围。

## 4. 必须保留的合同约束

API 以 `contracts/openapi.yaml` 为准，数据与事务以 `docs/specs/04-服务端数据与接口规格.md` 为准。设计时不得悄悄改名、合并状态或把错误变成空结果。

- 无当前周正常返回 `200` 与 `week: null`；网络/鉴权/内容不可用必须显示不同结果。
- `played` 与 `skipped` 才是可写状态；`unrecorded` 与 `future` 为派生显示状态。
- 身份与归属检查先于幂等缓存；同ID同载荷重放原结果，同ID不同载荷冲突。
- 原操作重放先于动态版本/日期/修订检查，避免丢失响应后的重试被误认为新操作。
- 内容版本与内容格式版本不同；新包只影响新计划。快照是历史事实，不能靠当前卡片JOIN重建旧内容。
- 多设备、公开账号和运行时管理界面不在当前范围。

## 5. 阶段交付

M1：内容选项、建周、读取当前/指定周、列表limit=1发现末周与未来排期、在线打卡；M2：历史列表界面、汇总、离线重放；M3：正式内容发布、快照和回滚验收；M4：建议和下周单卡调整。

设计必须让M1可独立实现。M4的模型、提示词和建议接口不应成为M1依赖；不选择模型供应商，不生成密钥或真实家庭样本。
