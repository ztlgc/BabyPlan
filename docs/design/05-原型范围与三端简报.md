# 原型范围与三端简报

版本：扩展需求原型准备 v0.1；日期：2026-11-11。状态：可以启动低保真；本文中的交互与排版选择为设计候选，不表示正式接口已经升级或方案已获视觉确认。

## 1. 需求依据与边界

[产品与三端架构讨论稿 v0.4](../BabyPlan-产品与三端架构讨论稿.md) 记载了用户已确认的扩展需求。本次保留原文，不将三端、内容管理或成长档案归档为失效需求。它也明确说明自己尚未替代正式规格。

| 已确认目标 | 本轮低保真需要表达 | 仍待确定或实现 |
| --- | --- | --- |
| 安卓、网页、后端；网页分家长区与内容管理区 | 三端信息架构和至少一条闭环；管理区独立于家长导航 | 部署、身份认证和正式权限合同 |
| 爸爸妈妈谁有空谁带、谁带谁记 | 陪伴者与添加者可不同；冲突时保留双方内容 | 邀请、账号恢复、同步与合并合同 |
| 自动安排；一天多个内容块 | 打开可看安排，临时换项、缩短、跳过；历史不成为补做清单 | 编排算法、替换边界、自动生成触发与事务 |
| 工作日一小时纯亲子，分散在16:00～20:00，晚饭约17:30 | 弹性三段与可拆分预算；不用倒计时或完成率催促 | 午睡、入睡与周末作息；三段窗口仍是候选 |
| 中英共读、已有书籍、阶段支持到3岁 | 书架、原创话术、适龄支持说明 | 家庭实际版本、书目审读、版权与点读兼容 |
| 照片、第一次、原话、小故事、身高体重 | 成长记录、上传状态、测量表和本人趋势入口 | 生日采集、标准选择、媒体授权与存储、导出删除规则 |

不设发育分数、排行、连续奖励或英语达标等级；不假定点读笔可控制、绘本可点读或封面可转载。成长“第一次”由家长确认，不由一次参与自动推断。无精确年龄和匹配参考资料时，不显示百分位或医学结论。

## 3. 默认设计轮次与完成条件

第一轮先做安卓低保真：今天安排 → 活动/共读详情 → 记录参与和可选反馈 → 回到今天；再做另一位家长看到结果、修改冲突、离线待同步。补充书架、阶段、成长和设置的入口与一条代表流程。

第二轮做网页家长区：查看同一天 → 查看阶段路线 → 整理家中书目 → 调整一项 → 查看成长与打印预览。网页复用同一家庭视角和术语，不另外复制一套数据模型。

第三轮做内容管理区：草稿 → 送审 → 审阅 → 发布前确认 → 发布成功/失败 → 撤回确认。草稿不进入家庭安排；已开展或被家长改过的项不自动重排。草稿、审核、发布权限用虚构角色模拟，实际角色分配和撤回对未开展项的影响须在确认页列为待定。

三端是同一产品原型的组成部分，编号分别使用 N / W / C。页面与中文文案见 [原型状态与文案清单](03-原型状态与文案清单.md)。评审入口允许选择成员、离线、冲突、加载、失败和权限；这些模拟控件不进入产品导航。所有后端结果、通知、照片上传与同步均明确标“模拟”。

首轮通过条件：主路径可点通，错误可恢复，未保存取消不写入，参与者与添加者有区别，未来日期不误报漏记，页面在360/412逻辑宽度下可滚动；按P用例逐项记录未覆盖项。低保真不用等待最终配色、正式内容包、HTTPS、真机或数据库。

## 4. 三端布局候选与视觉交付

安卓沿用讨论稿中的候选四入口：今天 / 阶段指引 / 书架与活动 / 成长，设置从页面工具入口进入；这一导航尚需低保真评审。今天优先显示可直接开展的内容与材料，已记项可收起，不以大插画占据首屏。

网页家长区按同样概念组织，宽屏可以并列今日安排与详情，窄屏折回单列。内容管理区单独入口、明显身份和权限提示，不把内容发布操作放入家长页面。后端交付技术说明、对象关系与异常时序，不虚构“服务已运行”。

候选变量、组件、资源与可访问性见 [视觉与组件基线](04-视觉与组件基线.md)。已有PNG仅是局部风格参考，既不是品牌确认，也不是可点击交付。配色确认在低保真通过之后进行。

## 5. 数据与交接

- 扩展原型读取 `content/design/expanded-prototype.json`，搭配 [虚构一天说明](06-虚构一天与数据说明.md)：纯虚构家庭、原创内容与固定时钟；它不是API响应、内容导入包或真实用户记录。
- `content/design/design-scenarios.json` 继续仅验证旧A页面；不将扩展对象塞入旧Week结构。
- 本轮不需要真实书封面、家庭照片或身高体重。照片用占位卡，测量仅演示录入、空态和表格；曲线绘制及参考标准在后续设计中单独核对。
- 组件说明必须给字段映射、可选字段缺失、保存中/失败/禁用、双主题和字号放大行为。资源清单列临时图标与待制作项，避免把完整图标体系当作低保真前置。
- 服务设计需要列新对象与旧合同的差异，不直接生成可被误认为正式接口的路径或请求示例。

## 6. 仍需决策的项目

| 项目 | 本轮采用的可逆处理 | 必须解决的节点 |
| --- | --- | --- |
| 午睡、入睡和周末安排 | 睡前用相对窗口，周末不加量 | 家庭安排确认前 |
| 登录、加入家庭、账号恢复 | 假定已连接的演示家庭，可切换虚构成员；连接页仅画恢复状态 | 正式身份合同和开发前 |
| 自动生成与换项 | 本地候选安排，用户调整有明确确认；不实际定时生成 | 编排和数据合同升级前 |
| 成长资料与生日 | 只填演示月龄；测量录入表不推算参考百分位 | 参考曲线设计、隐私和实现前 |
| 权限和发布撤回 | 虚构编辑/审阅角色演示；撤回影响范围显式标待定 | 内容发布规则定稿前 |
| 视觉偏好 | 用可替换候选token，低保真灰阶优先 | 高保真方案确认前 |

这些项目保留在设计审阅清单中，无需为了开始低保真一次性收集所有家庭资料。扩展阶段按18～23、24～29、30～35月和36月总结呈现；旧`m24_35`不能直接当作两个新阶段的内容已齐全。当前只提供一个七段结构的指引示例，其他阶段允许显示待补。后端的ExportJob、Observation、ReadingSession/ActivitySession等仍只有概念，样本不冒充完整对象合同。

## 7. 可直接交给设计工具的提示词

> 目标：为BabyPlan做扩展需求的中文三端低保真原型，先验证信息层级、路径与异常恢复。先读项目根目录CLAUDE.md、本文件、原型状态与文案清单、视觉与组件基线、虚构一天与数据说明、产品与三端架构讨论稿v0.4，并加载expanded-prototype.json；原型默认是N/W/C页面与P验收，不是旧A页面/M1合同。
>
> 用户是家庭中的两位家长；系统自动提供多个共读和游戏内容块，工作日60分钟是可拆分的候选预算，可缩短或跳过，不是考核。已有书籍优先，英语提供原创句子、中文意思、时机与动作；不承诺控制点读笔。先做安卓今天→详情→记录→另一成员看到→冲突/离线恢复，再补阶段、书架、成长、设置；接着做家长网页整理与打印、内容管理区草稿→审核→发布/失败→撤回确认。管理操作与家长入口分开。
>
> 格式：可滚动、可点击HTML/React原型；安卓按360/412逻辑宽度，家长和管理网页按1280宽并核对768/360重排。布局：今天优先内容、材料、怎么玩与怎么说，正文初始参考16，48逻辑像素触控目标，支持200%字号。低保真先灰阶；高保真才试用候选颜色。用系统中文字体，层级清楚、温和安静，不加计分、庆祝动画或大面积装饰。
>
> 文案按清单；内容按字段渲染，可选内容缺失整段省略。用固定虚构时钟与成员；照片只用占位。加入独立审阅面板切换加载、失败、空态、断网、媒体待上传、权限、并发冲突和不同角色。不得发送真实请求、上传真实数据、将本地交互称作通知/SQLite/真实同步。旧OpenAPI只覆盖一日一卡M1/M2，不能承载扩展对象。
>
> 交付原型源文件、启动入口、页面/状态/P用例映射、候选token与组件状态、资源清单、Flutter与Web交接说明及未决策项。任何新规则标候选，任何合同差异单列；不改现有合同迁就原型。低保真通过后再提出高保真方案，不把现有PNG当作已确认品牌。
