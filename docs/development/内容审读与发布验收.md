# BabyPlan 内容审读与发布验收

计划基线：2026-11-13。本文是开发计划附件，依据 `docs/v2/` 与 `contracts/v2/`，不是已执行的人工审核、家庭试玩或上线报告。

当前事实：24 张活动卡仍为 `candidate/draft`，专业审阅状态为 `not_reviewed`，家庭试玩状态为 `not_started`；24～36 月只有阶段支持设计，没有完整活动包。本轮进行了文档核对与内存校验探针，未修复合同、校验器或产品代码。

## 1. 三种用途与放行边界

以 [产品 Q11](../v2/01-产品定义与决策.md) 为准：家庭试用允许同一人承担编辑、审读与发布角色，但必须明确自审并保留真实记录；公开发布要求独立审阅。

| 用途 | 可以使用什么 | 放行条件 | 不能被描述成什么 |
| --- | --- | --- | --- |
| 工程测试 | 虚构家庭、候选素材、专用测试内容与故障样例 | 与真实使用环境分离；界面或构建标识说明测试用途；不借测试开关绕过真实发布门禁 | 已审核课程、已真实同步、已通过家庭试玩 |
| 私人家庭试用 | 已逐卡人工审读、无待处理安全疑虑的内容 | 来源范围、材料、步骤、停止出口、语言与权属经过人工审读；自审如实标记；绑定具体修订与正文 hash；有试用范围与反馈记录 | 独立审阅、专业认证、适合所有孩子 |
| 正式发布 | 固定版本、可追溯的已审核内容及适用的试玩结果 | 校验通过；发布角色与证据有效；正文修改使旧审批失效；撤回与恢复机制可用；公开发布另须独立审阅 | 只把 JSON 状态改为通过就算完成审核 |

“正式发布”需明确目标环境：家庭长期使用仍可保持私有；不能因为进入稳定版本就自动开启公开访问。对公开发布的独立审阅，不接受同一主体换账号冒充独立审阅者。

私人试用不额外要求所有条目先取得外部专业签字。`expert=not_reviewed` 应如实保留，不能为通过结构校验而改写事实。有发育解释、动作或材料安全疑虑的具体条目先停用，记录问题并转相应专业核验；其他已符合私人试用条件的条目与工程开发可以继续。

首次试玩无需等待完整 App：可以使用已完成试用前人工审读的打印手册或受控候选预览。首次试用的准入证据与试用后的反馈证据应分开，避免“必须先完成试玩才能开始试玩”的循环。

## 3. 后续证据模板的必需字段

以下是模板字段要求，并非已经完成的审核记录。模板建立后初始状态应是“待审/未开始”，不预填审读者、通过时间或成功结论。私人证据可存审核台账或私有数据库，不必全部下发到家长端内容包。

### 3.1 逐卡与阶段支持审读记录

| 字段 | 要求 |
| --- | --- |
| evidenceId / recordType | 唯一证据 ID；区分活动卡与阶段支持 |
| activityId 或 guideId、revision、contentHash | 绑定实际审读的不可变正文；正文有改动时旧证据不得自动覆盖新稿 |
| intendedEnvironment | 工程测试、私人试用或公开发布；与实际发布目标一致 |
| authorIdentity / reviewerIdentity / reviewedAt | 真实作者与审读主体、实际审读时间；不得填不存在的人或时间 |
| selfReviewed | 服务端根据真实主体关系计算或复核；同一人多角色如实标记 |
| sourceScope | 来源 ID/链接、核验时间、支持本卡的具体范围及不能推出的结论 |
| ageAndSafety | 适用年龄表达、材料和场地条件、成人参与、易误读动作、停止出口、尚存疑点 |
| languageReview | 中文指令清晰度；英语原句、中文含义、使用时机是否对应 |
| rightsEvidence | 原创说明；如使用授权资源，保存授权范围与证据引用，不只填写 licensed |
| decision / issues / requiredChanges | 通过、退回或暂停；具体理由、待改事项及负责人 |
| expertStatus / expertEvidenceId | 如实保留未专业审阅状态；只有真实发生相应核验时才登记引用 |
| recheckOf | 修改后的复核关系；明确哪些意见已处理、哪些仍未解决 |

审读不要求对孩子进行能力考核。来源节点不是训练目标，完成活动也不是“掌握”或“达标”的证明。

### 3.2 首周试玩记录

| 字段 | 要求 |
| --- | --- |
| trialId、contentVersion、cardRevision/hash | 定位实际使用的内容；不得仅写“最新版” |
| trialEnvironment / productBuild | 打印手册、受控预览或 App；使用 App 时记录构建版本 |
| startedAt、observedDates、status | 实际开始与观察日期；未开展或中断如实记录，不能自动填 completed |
| adultParticipant | 实际陪伴者的最少标识；不要求收集儿童姓名、照片或生日 |
| understandability | 大人是否能在约 30 秒理解玩法；这是待验证的设计目标，不是已达成结果 |
| materials / steps | 材料是否能找到、步骤是否过长、哪些描述引起疑惑 |
| responseAndStopping | 宝宝只看、不参与或想停时，家长是否有自然出口；不记录成能力分数 |
| recordingBurden / handoff | 记录是否费事，另一位家长能否接续了解情况 |
| issueSeverity / action | 文案问题、操作问题或需暂停条目的疑虑；后者先停用再核验 |
| feedback / revisionFollowup | 原始反馈与后续修订关联；不把“没玩”自动解释为不喜欢 |

七天安排从实际开始日算，不要求周一开始。按家庭自然节奏观察首周，不要求每天做满六项或补完分钟数。尚未实际试玩的卡保持“未试玩”；一周里未出现的候选卡不能因为属于同一个包就自动获得试玩结论。

### 3.3 构建、设备与发布验收记录

记录至少包括：构建版本及源码标识、内容版本、目标环境、设备型号与 Android 版本、用例编号、执行人、实际步骤、结果、失败截图或脱敏日志、未验证项、缺陷处理状态。使用模拟器时明确标注，不能写成真机通过。

备份恢复记录另包含：备份 ID 与生成时间、数据库及媒体清单/hash、恢复环境、恢复开始/结束时间、恢复点、抽样对象与权限验证、永久删除墓碑重放结果、遗漏与失败项。RPO 24 小时、RTO 4 小时是设计目标；只有实际演练结果能说明是否达到。

发布记录另包含：固定修订集合、正文 hash、证据引用、发布人和实际时间、发布目标环境、独立/自审关系、前一版本、失败回退结果、撤回原因和传播验证。发布成功不能仅由前端提示证明。

## 6. 本轮查到的具体缺口

定位行号来自 2026-11-13 的检查快照，后续修改可能移动；修复时以相应章节和字段为准。

1. **发布环境与审核状态不一致。** `docs/v2/01-产品定义与决策.md:53` 允许私人试用自审；`contracts/v2/content-package.schema.json:622–653` 却对所有 release 强制 `expert=reviewed`、`familyTrial=completed`；`contracts/v2/openapi.yaml:1993` 对私人试用也要求试玩证据。C01 需区分首次试用准入与试玩完成，不能通过修改事实状态绕过。
2. **证据结构不足。** 内容规范 `04-内容体系与首周.md:72–76` 要求审读人、日期、意见、试玩与 hash。Schema 的 `review`（28–58 行）只有状态；API 的审核请求（1958–1988 行）与发布请求（1990–2031 行）尚无明确证据引用。需设计服务端证据实体、实际身份关系、修订绑定及失效规则。
3. **核对时旧内容入口仍指向 v1；本轮已修正导航。** 原 `content/README.md:7–20` 要求 `schemaVersion: 1`、六张旧卡与旧 `--release` 命令。主代理已补新版入口并将旧说明标记为历史；v2 生产导入和门禁仍待 P0-05/A-05 实现。
4. **校验器不是生产导入器。** `tools/validate_v2_design.py:9–12` 固定读候选文件；14–43 行在 Schema 报错后仍直接索引数据。需支持指定输入、结构错误安全返回、纯校验模式与清楚退出码；导入需事务，不能失败后留下半包。
5. **语义反例覆盖不足。** 同一脚本 37–42 行未完整核对阶段来源月龄、年龄档唯一性和证据引用。API 审核 checks（1968–1978 行）没有 `uniqueItems`；实现必须核对四个不同检查项，而非只按长度判断通过。
6. **真实范围需要持续保留。** `content/candidate/babyplan-18-23-v2.json:5–10` 仍未审未试玩；`04-内容体系与首周.md:60` 说明后续年龄仅有阶段支持；`06-来源与核验.md:12` 的卫健委 PDF 未完成完整复核；`07-验证报告.md:42–46` 明确没有真机、服务部署与家庭试玩验收。

除第3项入口导航已修正外，以上合同、校验器与产品行为仍是后续任务，不代表本轮已经修复。

## 7. 本轮只读内存探针

执行方式：读取现有文件，用 Python AST 只提取 `validate_content` 函数，在内存副本上修改字段并运行；没有执行脚本顶层的报告写入逻辑，没有修改候选文件、Schema 或测试报告。

| 探针 | 实际结果 | 对开发计划的意义 |
| --- | --- | --- |
| 原候选包 | 通过 | 当前设计输入与校验器匹配 |
| 删除 cards | 抛 KeyError | 生产导入前需要结构错误短路和统一错误返回 |
| 18 月阶段的 sourceAgeMonths 改为 36 | 通过 | 补来源节点与阶段适用范围的语义约束 |
| 重复一个年龄档定义 | 通过 | 补稳定 ID 唯一性与档位完整性约束 |
| 权属改成 licensed，但没有授权证据 | 通过 | 正式发布校验真实证据引用，不只看枚举 |
| 仅将包与所有卡的审核状态改成通过 | release 结构检查通过 | JSON 状态不是审核真实性证明；发布端必须核对服务端持有的证据 |

这些探针不表示存在一个已部署服务的漏洞，也不表示问题已修复；它们说明从设计校验器升级到真实导入/发布流程时应补哪些验证。不要把本表重新包装成产品测试通过记录。

## 8. 并行边界与验证节奏

- 合同负责人独占 `contracts/v2/**` 与共享 DTO/校验规则；其他代理提交变更建议，由负责人统一修改与通知消费者。
- 内容负责人独占内容源与审读草案。先明确生成器和内容文件谁是权威源，再生成派生 JSON/原型数据，不让不同代理分别编辑三份副本。
- QA 代理独占指定测试目录和验收矩阵，实际审读者、实际设备操作者的结果独立登记。主代理复核真实文件与证据，不仅复述子代理的成功结论。
- 主代理负责集成、根入口、状态汇总和打包；同一时刻一个文件只有一个写入负责人。没有 Git 时按目录隔离，不假设 worktree 已可用。
- 优先验证身份隔离、数据丢失/重复、冲突恢复、内容撤回与媒体恢复。普通文案或静态布局只做相关预览；没有新变更、失败或未解决疑点，不反复全量跑旧原型测试。
- 每次检查注明对象：设计原型、实际 API、Flutter 模拟器、Android 真机、私人内容试玩或恢复环境。不同层次证据不能互相替代。

本附件仅新增计划与核对记录，尚未产生真实审核签字、真实家庭记录、真机验收或发布结果。
