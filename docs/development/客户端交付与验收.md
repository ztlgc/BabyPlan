2026-11-13 · Android 与家长网页开发附件

**实施状态（BabyPlan v0.1.3）：** 本文列出的 Flutter、真实账号、增量/完整同步、提醒配置、成长媒体和网页能力已经形成软件实现；自动化、真实 HTTP 和构建证据见[开发与交付验证报告](../implementation/开发与交付验证报告-2026-11-13.md)。真实 Android 通知送达、系统照片选择器、覆盖升级、双真机断网与生产部署仍未验收，不能因为软件已构建就标成真机通过。下文保留交付计划和验收边界，合同缺口表记录的是开工时的核对背景。

依据：[产品定义](../v2/01-产品定义与决策.md)、[界面与交互](../v2/02-界面与交互设计.md)、[技术架构](../v2/03-技术架构与数据.md)、[实施验收](../v2/05-实施与验收.md)、[v2 接口合同](../../contracts/v2/openapi.yaml)。旧 v1 不用于本次实现。

## 1. 四个交付版本

| 版本 | 家长能看到的结果 | 必须完成的能力 | 本阶段完成条件 |
| --- | --- | --- | --- |
| R0 首个开发 APK | 手机上的真实 Flutter 界面，可以看今天、活动详情和页面状态 | 工程构建、主题/组件/导航；只读模型与持久化基础可先做最小切片 | APK 可复现构建、可安装启动；页面不是浏览器套壳；明确标记开发数据；安装和界面检查有记录 |
| R1 双人基础闭环 | 两位家长各自登录，同看一个孩子的当天安排，一端记录另一端可读 | 私人账号/邀请、孩子档案、真实计划/参与、SQLite、操作队列、同步骨架、基础冲突保留 | 两个独立客户端从真实 API 读写；重复提交不重复；重启不丢已存数据；不同家庭不可访问 |
| R2 可日用 MVP | 能看未来七天、换活动、用轻松模式、离线记录并收到每日提醒 | 完整冲突恢复、离线/重同步、活动库/书架/阶段、Android 提醒、内容撤回阻断 | 真机验证离线重启、双人冲突、通知权限/省电/重启、跨午夜；已记录内容受保护；首批内容满足对应试用门禁 |
| R3 成长与家长网页 | 记录原话、故事、第一次和测量，保存照片，网页查看/打印/导出 | 成长文字、测量、独立媒体队列、家庭与隐私管理；家长网页真实 API 接入 | 文字与照片分别恢复；跨端一致；导出有遗漏清单；回收/恢复/删除和家庭权限有证据 |

R0 不等待完整登录、双人同步、提醒或成长功能。允许使用**明确标记且与正常配置隔离**的虚构联调数据；不得把候选育儿内容改标成正式发布内容。R0 只能称为“开发 APK”，不能称为可日用版本。

R1 允许仅做必要的同步切片，但必须从开始就持久化 operationId、对象修订、草稿、outbox 与同步状态。暂未自动处理的冲突应保留双方并明确提示，不能静默覆盖。R2 再完成全部恢复交互与异常覆盖。

R3 可进一步拆成“文字与测量”“照片”“网页与导出”三个小交付，不要求一次完成。完整网页不阻塞 R2 手机日用功能。

R2 私人试用前固定 applicationId、签名来源和版本递增方式，并实际做一次覆盖升级，确认本地记录和待传草稿保留。不能等 R3 或最终交付才决定签名，导致家长必须卸载丢掉本地内容。签名秘密不放入源码或交付包。

## 4. 按阶段补齐合同

以下是 2026-11-13 开工时对合同的核对记录，供追溯为什么新增相应接口。当前 OpenAPI 已增长到 69 个操作并补上这些路径；后续修改仍由主代理/合同负责人同步规范、生成脚本与校验。

| 最晚闭合节点 | 缺口与依据 | 必须形成的实现决定 |
| --- | --- | --- |
| R1 身份实现前 | [OpenAPI](../../contracts/v2/openapi.yaml) 第 17 行声明手机刷新令牌安全交付，但登录响应第 28–42 行、刷新响应第 124–133 行只有访问令牌和过期时间；第 111 行要求刷新 Cookie 或 Header | 固定手机首次/旋转后刷新令牌的响应字段或响应头、过期与重用语义；明确 Web Cookie 与手机安全存储的差异 |
| R1 参与实现前 | [界面规格](../v2/02-界面与交互设计.md) 第 31 行承诺撤销；OpenAPI 第 796–826 行仅有参与 PUT | 定义撤销接口、revision 和删除变更；不能撤掉另一家长较新更新；明确未同步本地撤销和已同步撤销的处理 |
| R1 家庭界面前 | 界面规格第 77 行要求显示昵称；OpenAPI 第 2197–2212 行 Member 只有 userId/role/active | 成员读模型提供显示名或稳定安全标签；bootstrap/快照提供一致来源；不能把所有人显示成同一个“另一位家长” |
| R1 同步切片前 | OpenAPI Change 枚举未覆盖 child/member，而孩子年龄和家庭成员可改变 | 固定成员与孩子资料刷新方式：增量实体或必需的 bootstrap 刷新；权限失效必须先处理，不能继续用旧成员资料写入 |
| R2 换项实现前 | 界面规格第 30–32 行、OpenAPI 第 758–795 行有开始接口、PlanItem 有 lockedByParent，但产品触发和恢复语义未闭合 | 明确什么动作算开始、家长修改怎样锁定、误操作怎样恢复；建议浏览详情只读；客户端不能各自猜测 |
| R2 提醒实现前 | [产品规格](../v2/01-产品定义与决策.md) 第 47 行要求每账号指定一台提醒设备；当前无设备/提醒偏好接口 | 定义设备绑定、启停、时刻、设备更换、在线撤销；本地系统权限与服务端偏好分别表达；明确旧设备离线限制 |
| R2 缓存/恢复完成前 | 产品规格第 56 行要求未来 7 天＋近 30 天；OpenAPI 第 958–1037 行给出受总量上限约束的家庭快照 | 确定一致性快照范围、常规缓存清理和历史读取方式；待传/冲突项永不按普通缓存删除；数据达到上限须有可恢复路径 |
| R2 个性化编排前 | [架构](../v2/03-技术架构与数据.md) 自动安排依赖家庭材料/排除项/语言偏好，Family 模型未完整表达 | 明确首版支持哪些偏好、默认值与读写接口；未采集的事实不能当已确认材料或偏好参与打分 |
| R3 回收功能前 | 产品规格第 58 行及 OpenAPI 第 1145 行承诺软删除可恢复，但没有恢复路径 | 补回收列表/恢复以及权限、revision、保留期限；区分可恢复删除与永久删除；确定适用实体 |
| R3 成长列表前 | 现有快照有总量上限，缺少面向长期成长历史的日期/游标查询 | 定义成长历史与筛选读取；避免几年的记录只靠每次全量快照；分页不能破坏同步一致性 |

这批缺口属于实现细化，不需要再向非技术用户逐项提问。合同负责人基于已确定产品目标作决定并记录原因；只有真实家庭事实不能推断时，才保留空值或待配置状态。

## 5. 真实验收与证据

| 版本 | 需要执行的真实检查 | 证据与完成判定 |
| --- | --- | --- |
| R0 | 构建、安装启动、路由、大小字/深浅主题、系统返回/键盘 | 构建命令及退出结果、APK 与摘要、设备/模拟器系统信息、截图；只证明工程与界面 |
| R1 | 两个账号/同一家庭，两个独立客户端；重复请求、重启读回、不同家庭越权 | 客户端与真实 API 联调记录；DB 结果证明没有重复写；真实双设备验证单列；对应 V201/V202/V205/V207/V212 |
| R2 | 飞行模式保存→杀进程→重启→联网；两人冲突；游标失效；跨午夜；通知被拒/重启/省电；安全撤回 | 自动化结果加真机操作记录；双方草稿可恢复；提醒真实到达/抑制情况；对应 V203–V209、V213、V215、V217 |
| R3 | 文本保存而照片失败、选图 URI 失效、断点恢复、不同家庭读媒体、回收恢复、导出遗漏、手机/网页并发 | 文字与媒体各自的数据库/界面状态；授权失败证据；实际下载/打印产物；对应 V210–V213、V216、V217 |

测试按风险分层：纯业务单测覆盖日期/预算保护/队列状态；Repository 集成测试覆盖真实 SQLite 事务与迁移；API 联调覆盖鉴权/幂等/冲突；原生集成与真机验证覆盖生命周期、通知和选图；网页测试覆盖真实会话、编辑、下载和打印。不要为每个静态文案写重复断言，也不把一套浏览器截图测试当成整个产品验收。

若当时没有连接真机，可继续模拟器、服务端与自动化联调，真实设备项标记“待验证”；不能把未执行写成通过，不能因此声称日用版本已经完整验收。版本内未完成的功能应隐藏或明确未接入，不显示假成功。

每个版本至少归档：构建标识、APK 路径与哈希、API/数据库迁移版本、使用的内容版本和状态、执行环境、通过/失败/未执行项、已知问题、升级/回退说明。不要将真实家庭记录、令牌或照片打入测试报告和交付包。

## 6. 子代理文件分工与集成顺序

| 责任 | 独占写入范围 | 协作规则 |

集成顺序：合同切片冻结 → 服务端与客户端独立实现 → 主代理检查实际文件/差异 → 真实 API 联调 → 必要回归 → APK/网页产物 → 对照验收记录。共享类型改变时先通知所有消费者，不在代理各自分支里悄悄分叉。

当前没有 Git 仓库，不能假定已有 worktree 隔离；先通过互斥目录分工。后续若建立 Git，再按主计划使用隔离分支或 worktree。子代理不自行提交、推送、发布、部署或修改全局模型与认证配置。

每个工作包交接必须说明：修改文件、已接入的真实能力、仍为替身的部分、实际执行检查、未解决问题，以及是否影响合同/迁移/内容。子代理声称“完成”后仍由主代理集成核验。
