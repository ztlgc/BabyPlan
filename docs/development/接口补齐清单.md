# BabyPlan 接口补齐清单

编制日期：2026-11-13。状态：开发计划，尚未修改或实现接口。

本清单以 `docs/v2/`、`contracts/v2/` 和产品 Q01—Q17 为依据，把设计合同中需要落到代码的空白分阶段补齐。它不要求在首个 APK 前实现全部 44 个设计接口。P0 只冻结首个两人协作闭环所需的公共规则及接口；成长、媒体与工作台按后续阶段补齐。

**统一负责人：主代理。** 本清单全部 GAP 的最终合同修改、公共类型、数据库迁移顺序和接口版本由主代理负责。子代理可以在分配范围内提出补丁或实现模块，但不能各自改动共享合同。`tools/build_v2_contracts.py` 是当前生成源，修改必须覆盖生成源、生成合同、语义校验及对应文档，不能只改 YAML。

文中的路径相对项目根目录；行号来自本次只读核对，实施时以内容定位为准。全部 15 项当前状态均为「待实施」。

## P0：首个两人协作闭环前

### GAP-01 完整的登录、刷新和 Web 会话合同

- **依据**：`contracts/v2/openapi.yaml:13–151`、`:435–465`、`:2124–2139`；`docs/v2/03-技术架构与数据.md:131`。
- **现状**：登录、邀请兑换及刷新响应声明了访问令牌，但没有明确手机刷新令牌的响应载体。Cookie 与 CSRF 规则主要停留在描述文字。
- **拟补内容**：明确手机与 Web 的会话模式及选择方式；定义首次和每次轮转的刷新令牌交付、失效与复用处理。为 Web 定义 Cookie 属性、CSRF 获取/提交规则、跨来源拒绝策略。固定会话期限与设备绑定规则，并给出不含真实凭证的请求响应样例。认证字段从日志、错误回显和幂等结果中排除或安全处理。
- **验收**：手机仅凭合同即可实现首次登录、一次轮转、退出和失效恢复；旧刷新令牌重用按约定撤销；Web 缺少/伪造 CSRF 的写操作失败；普通家庭与内容角色使用同一认证实现、各自授权。
- **边界**：P0 完成公共约定与手机闭环；完整网页界面在 C 阶段接入，不能到那时才改变认证含义。

### GAP-02 第一次建立 owner 与账号恢复的管理流程

- **依据**：`docs/v2/01-产品定义与决策.md:43`；`docs/v2/03-技术架构与数据.md:131`；`contracts/v2/openapi.yaml:172–255`、`:307–350`。
- **现状**：已决定私人邀请制与一次性引导，但缺少首次 owner 创建、管理端签发恢复凭证的可执行合同；无邮件时的安全交付方式未写成运维流程。
- **拟补内容**：首版采用私有管理命令完成首次 owner 引导和恢复凭证签发，避免引入公开注册。规定一次性、有效期、摘要存储、管理执行权限、账号已存在时的行为及恢复后会话撤销规则。家长恢复请求采用一致响应；无邮件服务时由部署管理员安全交付链接，不把邮件平台作为本地开工依赖。
- **验收**：全新数据库能按文档创建首个家庭；引导及恢复凭证不能重复消费；邀请兑换并发只成功一次；恢复不会覆盖其他账号或泄露邮箱存在性；日志中没有凭证正文。

### GAP-03 统一授权、幂等、修订与冲突载荷

- **依据**：`docs/v2/03-技术架构与数据.md:75–79`、`:103–121`；`contracts/v2/openapi.yaml:796–825`、`:2141–2182`、`:2734–2766`。
- **现状**：公共原则已写明，但 `Error.details` 是任意对象，`current/submitted` 没有可稳定解析的类型；首次创建、再次写入、不同对象修订域和匿名邀请兑换的幂等身份需要统一。
- **拟补内容**：定义首版所需错误码和结构化冲突对象，至少包含对象类型、对象 ID、当前修订、当前值、提交值和允许的恢复动作。明确定义 `baseRevision=0`、Plan/PlanItem/Participation 各自的修订边界；规范请求摘要、同操作重放、同 ID 异请求拒绝、匿名邀请兑换的去重作用域，以及权限校验必须先于幂等响应重放。将内容角色与家庭角色矩阵落为一份公共权限表。
- **验收**：超时重试只写一次；同 ID 不同请求返回可辨认的冲突；已撤权成员不能重放旧成功结果；两人首次相容的 played 能合并，不相容值保留双方；客户端不靠解析中文错误文案恢复。
- **客户端操作补齐**：参与摘要的撤销须有受 revision 保护的接口及删除变更，不能撤掉另一家长较新编辑；未同步本地撤销与已同步撤销分别定义。

### GAP-04 家庭事实的完整同步与一致性游标

- **依据**：`contracts/v2/openapi.yaml:256–306`、`:891–1049`、`:2995–3037`；`docs/v2/03-技术架构与数据.md:75`、`:121`。
- **现状**：Change 包含计划、参与和成长等对象，但没有 child/family/member；snapshot 含孩子，不含完整家庭成员事实。仅首次 bootstrap 无法说明年龄和成员改变如何传播。单调序列还需定义与事务提交的关系。
- **拟补内容**：补齐首版需要的家庭、成员、孩子变更类型，或明确触发重新 bootstrap 的协议；变更包括撤权及删除。规定 snapshot 与 cursor 的同一一致性读点、增量排序、分页边界、空批次 cursor 和重放规则。选用不会因较小序列事务较晚提交而漏事件的分配/读取机制；不能仅用数据库自增序号就假定提交顺序一致。
- **验收**：两端能看到同一孩子和成员列表；年龄更新后另一端可见；撤权后后续请求失败；在快照/分页同时写入和乱序提交下，没有漏记录、重复实体或删除复活；所有家庭访问仍按当前成员关系校验。
- **显示模型**：成员返回可识别显示名或稳定安全标签，避免界面显示 UUID 或把多人统一显示成同一个“另一位家长”。

### GAP-05 内容的工程测试、私人试用与正式发布门禁

- **依据**：`docs/v2/01-产品定义与决策.md:53`（Q11）；`contracts/v2/content-package.schema.json:17–58`、`:623–654`；`contracts/v2/openapi.yaml:1520–1580`、`:1928–2031`。
- **现状**：包只有 candidate/release，release 要求 expert=reviewed 与 familyTrial=completed；发布接口又允许 private_trial/public。若不解释两层状态，容易把工程测试误称正式发布，或把「家庭试玩已完成」设成开始私人试玩的前提。
- **拟补内容**：统一内容包渠道、审核状态和发布环境的映射，明确三条路径：工程测试可用显式测试夹具及候选包，标识演示/测试且不伪造审核；私人试用需逐卡完成内容审读、来源范围、安全、语言及版权核对，可由同人承担多角色，记录自审人、版本和结论；正式公开发布要求独立审阅并满足正式门禁。私人试用不强加外部专业签字，也不要求试玩已结束才能开始试玩；expert 和 familyTrial 的实际状态如实保存。若需扩展渠道或门禁，先修订 Schema、导入器和 API，不以把候选状态改成已审核的方式绕过。
- **验收**：测试包不会被正式环境自动选入；私人试用可在如实标记未完成试玩时启动；同人自审明确展示且可追溯；公开发布拒绝自审冒充独立审核；没有证据就不能自动填写 expert=reviewed 或 familyTrial=completed。
- **边界**：首闭环只需导入流程和受控内容通道；完整审核工作台留到 D。

### GAP-06 计划快照、受保护项目与撤回覆盖的公共对象

- **依据**：`docs/v2/01-产品定义与决策.md:35`、`:46`、`:54`；`docs/v2/03-技术架构与数据.md:67–70`、`:85–93`；`contracts/v2/openapi.yaml:667–825`、`:2581–2684`、`:3038–3066`。
- **现状**：设计已有快照和 locked/started/participation，但轻松模式隐藏项的恢复、项目修订与参与修订的独立更新、撤回先于正文可见的读取顺序还需落实为可执行约定。
- **拟补内容**：明确 active/hidden 项目的持久化或等价保留方式、模式恢复原项的规则、保护项导致预算超过 20 分钟时的返回信息；参与变更不隐式覆盖计划。冻结安全撤回标识与原因对象，以及正文展示前取得撤回状态的同步规则；具体管理界面在 D 实现。
- **验收**：计划重新获取后原快照与记录不变；客户端能从服务端状态恢复隐藏项；已开展内容不被普通重排覆盖；测试撤回事件能够阻断缓存快照正文且保留参与历史；系统不把预算误写为实际分钟。

## B：日常使用版前

### GAP-07 家庭资源、语言与编排偏好的持久化

- **依据**：`docs/v2/03-技术架构与数据.md:83–89`；`docs/v2/02-界面与交互设计.md:39`；`contracts/v2/openapi.yaml:2213–2236`。
- **现状**：编排依赖家庭资源、排除材料、语言偏好，Family 合同没有相应字段和读写入口。
- **拟补内容**：建立最小偏好对象及默认值，明确家庭级与个人级字段、修改权限、revision 和同步事件。家庭资料缺省时采用文档中的安全默认，不根据「未记录」推断喜好；偏好变更只影响符合重排条件的未来项目。
- **验收**：两端使用相同家庭偏好；排除材料的卡不再入选；更新偏好不会改写已开始/已记录内容；冲突能保留用户输入。

### GAP-08 每账号一台提醒设备的注册与切换

- **依据**：`docs/v2/01-产品定义与决策.md:47`；`docs/v2/03-技术架构与数据.md:127`。
- **现状**：已决定本地非精确通知和每账号一台提醒设备，但缺少设备资格、启用/关闭、切换和失效的合同。
- **拟补内容**：定义提醒设备绑定、用户偏好及在线切换流程；通知仍在设备本地调度，服务端不承担精确送达。明确登出/成员退出/设备切换后旧设备停止调度的时机，并如实记录离线旧设备无法立即获知切换的边界；每 device/date 的实际送达去重由本地持久化。
- **验收**：在线切换只保留新设备资格；关闭、登出或全部处理后取消后续有效提醒；拒绝权限不反复弹框；20 点后不补发；重启/升级后的重排在安卓设备验证。

### GAP-09 离线窗口、过期队列及快照容量恢复

- **依据**：`docs/v2/01-产品定义与决策.md:56`；`docs/v2/03-技术架构与数据.md:117–121`；`contracts/v2/openapi.yaml:891–1044`。
- **现状**：已定义未来 7 天和近 30 天离线数据、90 天幂等保存，以及 snapshot 数量上限，但超过上限和游标过期时客户端如何完整恢复仍需闭合。
- **拟补内容**：规定缓存窗口、待上传草稿不受窗口清理影响、已处理操作与墓碑保留策略。定义稳定错误码及完整拉取方案；可采用分段快照或明确支持规模，但不能截断数据后称完整。明确过 90 天队列、撤权后本机草稿、连续两次修改同对象时的核对流程。
- **验收**：飞行模式杀进程后草稿/队列保留；晚到的成功响应不覆盖更晚本地修改；410 后重同步不丢待提交数据；超规模返回可恢复错误；旧队列不无脑重试产生重复记录。

## C：成长与家长网页前

### GAP-10 成长历史、观察与测量的查询和纠错边界

- **依据**：`contracts/v2/openapi.yaml:1050–1392`、`:2767–2868`；`docs/v2/01-产品定义与决策.md:51`；`docs/v2/02-界面与交互设计.md:48`。
- **现状**：写接口和全量 snapshot 已有，成长网页的历史筛选/分页、阶段观察纠错，以及字段组合校验的机器可执行约束未完整定义。
- **拟补内容**：补日期/类型筛选和稳定分页；明确观察追加还是可修改，并给纠错路径。约束身高/卧位身长/体重对应的方法与单位组合、业务日期及 firstConfirmed 语义。网页在线写入使用同一 revision、operationId 和权限规则。
- **验收**：连续翻页无重复或缺失；更正测量后各端一致；身高和卧位身长不会静默混画；未确认的第一次被拒绝；未来日期拒绝且保留输入。

### GAP-11 回收、恢复、永久删除与任务状态

- **依据**：`docs/v2/01-产品定义与决策.md:58`；`docs/v2/03-技术架构与数据.md:135`；`contracts/v2/openapi.yaml:1142–1181`、`:1790–1843`。
- **现状**：产品要求 30 天回收，合同有软删/永久删除但无回收列表与恢复入口；家庭删除返回 jobId，没有统一任务状态读取。
- **拟补内容**：定义可回收记录类型、列表、恢复、到期清理、立即永久删除和权限；提供删除任务状态及失败重试可见性。区分退出家庭、移除成员、删除家庭和账号处理，不用一个按钮承担不同后果。永久删除墓碑与媒体清理纳入恢复演练。
- **验收**：回收期内能恢复正确版本；已永久删除不可恢复；重复删除不新建重复任务；操作失败可查询真实状态；数据库恢复后不会复活永久删除内容。

### GAP-12 私有媒体上传、处理与下载权限

- **依据**：`docs/v2/01-产品定义与决策.md:50`；`docs/v2/03-技术架构与数据.md:133–135`；`contracts/v2/openapi.yaml:1588–1709`、`:2906–2950`。
- **现状**：三步上传与状态对象已有，尚需固定上传请求限制、异步失败原因、附件移除/孤儿清理、签名地址失效和撤权行为。
- **拟补内容**：给出 MIME/大小/实际解码限制、上传过期、完成重试、处理失败和对象存储适配器协议。定义正文与附件引用分开保存的顺序，照片 ready 的权威来源，以及附件移除如何清理。临时下载地址必须经当前家庭权限签发，清晰区分已有链接自然到期与撤权后不得再签发。
- **验收**：假 MIME、超限和错误家庭 ID 被拒；上传失败不丢故事；两次 complete 不重复处理；去除定位信息；本机预览不显示成另一端已收到；对象不得公开列举。

### GAP-13 导出格式、范围与完整性证据

- **依据**：`docs/v2/01-产品定义与决策.md:52`；`docs/v2/03-技术架构与数据.md:135`；`contracts/v2/openapi.yaml:1710–1789`、`:2951–2994`。
- **现状**：导出任务与 missingMedia 已设计，但 JSON/CSV/媒体 ZIP 的目录、版本、筛选含义和一致性时点尚未固定。
- **拟补内容**：冻结导出清单版本、日期范围及记录类型、时区、作者与快照保留、CSV 编码和附件路径；写入校验值及遗漏原因。下载链接按产品 Q10 设置 15 分钟有效，在创建和下载时检查权限；定义过期重建、任务失败和大文件边界。
- **验收**：JSON、CSV 与媒体清单互相可对应；过滤范围可复核；未上传/处理失败照片逐项列出；权限撤销后不能取得新链接；导出失败不被显示为已完成。

## D：内容工作台前

### GAP-14 管理工作台的列表、详情和审阅查询

- **依据**：`contracts/v2/openapi.yaml:1520–1580`、`:1844–2078`；`docs/v2/02-界面与交互设计.md:54`。
- **现状**：管理端只有变更操作，没有支撑内容库、草稿详情、审核队列、来源及发布历史的读取接口。正式 `/content/options` 不能用于读取草稿。
- **拟补内容**：补内容/修订/审核/发布的筛选分页和详情查询；区分 editor、reviewer、publisher、只读权限与家庭权限。审核详情必须指向固定正文修订，展示差异、来源和核验记录，不能加载“最新正文”替换正在审核的版本。
- **验收**：工作台可仅靠 API 完成全部列表与详情；无角色不可读草稿；内容角色不能访问家庭记录；编辑后的新版本不会沿用旧审核结果；分页与权限变化行为一致。

### GAP-15 发布证据、活跃版本与撤回影响

- **依据**：`docs/v2/01-产品定义与决策.md:53–54`；`docs/v2/03-技术架构与数据.md:65`、`:76`、`:93`；`contracts/v2/openapi.yaml:1989–2078`、`:3067–3117`；`contracts/v2/content-package.schema.json:623–654`。
- **现状**：发布体只有修订 ID 与环境，发布对象没有完整审核证据或活跃版本信息；普通回退与安全撤回的管理预览及影响统计需要明确。该阶段延续 GAP-05，不能另设互相矛盾的门禁。
- **拟补内容**：将证据绑定内容 hash/固定修订、审核者、时间、发布环境和自审标记；定义活跃 release 的原子切换、发布失败回退、历史不可变及撤回影响查询。普通回退仅影响允许重排的未来项目；安全撤回通过公共撤回协议阻断相关快照，保留历史记录。
- **验收**：未通过修订、证据不匹配、公开自审均拒绝发布；失败不切换活跃版本；编辑无法修改已发布正文；撤回事件可在两端重放；离线设备不假称已经得到实时撤回通知。

## 实现时的修订流程

1. 主代理在任务板认领本阶段 GAP，引用原设计及拟采用决定；遇到规则冲突，优先产品 Q01—Q17 与当前用户指令，写明选择及影响，不让不同模块自行解释。
2. 先修改 `tools/build_v2_contracts.py` 与相关业务文档，再重建 `contracts/v2/openapi.yaml`、内容 Schema；同步公共类型、示例、语义校验。逐项记录接口新增或行为变化，保留 v1 历史文件。
3. 对新增接口执行结构及引用检查；对同步、权限、发布状态等不能靠 Schema 表达的规则，补可执行的正反例和集成测试。现有 `tools/validate_v2_design.py` 只能证明已有结构检查，不能替代新行为测试。
4. 用同一合同与样例交给后端、Flutter 和 Web 代理，各自仅修改分配目录。共享文件、迁移编号和锁文件由主代理统一集成。合同若必须调整，先通知消费者再改，避免客户端各自打补丁。
5. 用真实 API 与客户端联调当前阶段的闭环。通过后记录合同版本、实现文件、实际执行的检查、结果和未验证项，才把 GAP 改为完成；只补文档或通过生成器不等于完成业务验收。
6. P0/B 的未解决项不能用模拟数据冒充完成。C/D 的未开始项保留在计划中，不阻塞与它们无依赖的首个 APK。部署、真机、审阅证据分别报告，不能用代理口头结论代替证据。
