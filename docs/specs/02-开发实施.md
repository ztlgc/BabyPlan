# 开发线：安卓与家庭服务端

先接演示内容包。Flutter App 负责界面、本地提醒和待同步打卡；Fastify + TypeScript 服务端用 PostgreSQL 保存内容版本、计划、打卡和周回顾。界面只使用通用字段渲染活动卡，不在页面里写死歌曲、数字、主题名或年龄段。

2026-11-11实施补充：本文件保留总体开发边界；具体行为以 [安卓交互与状态规格](03-安卓交互与状态规格.md)、[服务端数据与接口规格](04-服务端数据与接口规格.md)、[OpenAPI](../../contracts/openapi.yaml) 和 [分阶段验收](05-实施阶段与验收规格.md) 为准。先交付M1/M2合同，AI接口仅保留后续意图，M4补齐并发布合同后才能调用。设计输入见 [设计交接入口](../design/README.md)。

## App 与服务端的边界

| 模块 | 实施约定 |
| --- | --- |
| 今天页 | 显示已保存的当天任务：材料、步骤、台词，再按存在的字段显示儿歌、数量和英文。允许补记、改记和选一个反馈；开始计划和权限状态要看得见。 |
| 回顾页 | 本周及历史周都能看。把「一起玩了」「跳过」「未记录」分开；未来任务不算未记录，待同步记录提示同步。先展示程序汇总，再提供手动生成 AI 建议的入口。 |
| 设置 | 手机本地保存估算月龄及录入日、提醒时间和开关。首版一台手机，使用一个预置家庭凭证；服务端只收计划选用的档位，不收出生日期。 |
| 本地存储 | SQLite 缓存已下载的周计划和内容快照；打卡先保存本机，再发送。重新打开 App 时重试待同步项。参照 [Flutter 的离线读写模式](https://docs.flutter.dev/app-architecture/design-patterns/offline-first)。 |
| 安卓提醒 | 为有活动且本地未记录的日期排一条；记完取消，改时间撤旧重排。权限拒绝时显示关闭状态并可前往系统设置。按目标安卓机验收锁屏、改时、取消和通知点击。参照 [Android 通知权限说明](https://developer.android.com/develop/ui/compose/notifications/notification-permission)。 |

## 服务端的数据和接口

服务端保留内容包版本与激活指针。导入时先核对[格式和引用](../../contracts/content-package.schema.json)，再写入并切换；失败不更改当前包。演示包只进开发环境。相同包名、版本、内容重复导入无副作用；同一版本内容不同拒绝，修订必须递增版本。回滚只切回已保存的有效版本。

建周计划时按家庭本地日期生成 7 个稳定任务，任务保存 `cardId`、内容包版本和完整卡片快照。家庭内的周计划日期不可重叠，确保每天最多一张卡。活动日期与实际打卡时间分开：隔天补记仍归原日期。家庭时区在建周时保存，用于计算日期和回顾统计。下一周可以经家长确认换一张卡；已经开始的周不随内容更新改动。

| 最小接口 | 用途 |
| --- | --- |
| `GET /v1/content/options` | 返回当前可用的包名、版本、月龄档和计划模板摘要。App 根据估算月龄找档位；没有该档模板就提示待补。 |
| `POST /v1/weeks` | 根据 `requestId`、起始日、家庭时区、包版本、模板编号生成一周；可带已确认的 `suggestionId`。重复请求返回原计划；已过期的包选择要求刷新后再确认。 |
| `GET /v1/weeks/current`、`GET /v1/weeks/{weekId}` | 读当前或指定周，含每天的卡片快照和打卡。历史周列表使用 `GET /v1/weeks`。 |
| `PUT /v1/tasks/{taskId}/check-in` | 写入 `operationId`、状态（`played` 或 `skipped`）、可选标签和记录时间。服务端每任务只保留一个当前结果；同一次操作重传不重复生效。 |
| `GET /v1/weeks/{weekId}/summary` | 返回可核对的统计、记录和已有 AI 建议。 |
| `POST /v1/weeks/{weekId}/ai-review` | 根据已同步的记录生成或重用一条建议。内容变化后可重新生成。 |

反馈可留空。`played` 可选 `want_again`（还想再玩）；`skipped` 可选 `family_busy`（家里没空）、`child_tired`（宝宝累了）或 `time_unfit`（这个时段不方便）。手机按同一任务的操作顺序补传。响应丢失时重试原 `operationId`；本机已有更新的修改时，旧响应不能覆盖新结果。回顾统计以任务日期和最新已同步记录为准；若手机还有待同步项，提示同步后再生成 AI 建议。

服务端验证家庭凭证及每条记录的归属。调试使用演示包和虚构记录；家庭试用前配置私人访问和加密传输。模型密钥只在服务端，模型输入仅含活动编号或类别、计数、相对天数和结构化反馈。模型给出的替换建议必须引用有效记录、对应包中可用的卡、符合下一周档位；家长确认才生成新计划。数据不足或模型失败时，基础周报仍可看。

## 开工与验收顺序

1. **演示包与安卓真机。** 导入演示包、开始 7 天计划、真机看今天卡、锁屏收到提醒并点开、提交打卡；重开能从服务端读回。开发不等正式卡片。
2. **家庭连续使用。** 加手机缓存、离线写入和顺序补传。验收断网重开、重复提交、隔天补记、权限关闭、改时和打卡后取消提醒；补上基础周报。
3. **内容换包。** 演示包修改一句话并增加 `contentVersion`，同一个 APK 能在新周看到变化，旧周仍是原话；无效包被拒绝且已有内容可继续用。通过后导入正式 18～23 月内容。
4. **AI 与下周调整。** 用「同一活动两次标想再玩」「只有一条记录」「全未记录」的样例验证依据和无建议的情况。确认建议只换下周一天的卡，不重复建周、不改旧周。

第一个开发任务只做第 1 步。完整离线、多设备和模型都不影响这一步的真机验收。
