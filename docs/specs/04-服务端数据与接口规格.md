# 服务端数据与接口规格

本文与 [OpenAPI 3.1 合同](../../contracts/openapi.yaml)共同交付设计工具、Flutter 与 Fastify + TypeScript 开发者；规定行为和数据约束，不表示服务或 CLI 已实现。基础依据为 [总体框架](00-总体框架.md)、[开发实施](02-开发实施.md)、[内容合同](../../contracts/content-package.schema.json)和[演示包](../../content/demo/demo-content-package.json)。不更改内容合同。

本次明确实施阶段，并将原开发说明中 `suggestionId`、AI 接口与下周替换的设想留到 M4。M1～M3 可用请求不接收 `suggestionId`，不提供 AI 路由。当前首版无管理后台，内容导入、激活、回滚由本地运维 CLI 处理，不存在公开管理 API。

## 1. 交付阶段与产品边界

| 阶段 | 服务端及客户端交付 | 设计与验收边界 |
| --- | --- | --- |
| M1 | `GET /v1/content/options`、`POST /v1/weeks`、`GET /v1/weeks/current`、`GET /v1/weeks/{weekId}`、`GET /v1/weeks`、`PUT /v1/tasks/{taskId}/check-in`；开发环境导入演示包 | 开始、今天、按已知周编号读回、在线补记与改记；列表用limit=1发现末周和未来排期，历史浏览界面留M2；基础鉴权、幂等、快照和revision必须完成 |
| M2 | `GET /v1/weeks/{weekId}/summary`与历史周列表界面；SQLite 缓存、离线写入、同任务串行同步与冲突处理 | 展示历史周、基础回顾、本地待同步与失败状态；离线不是一个额外的批量写 API |
| M3 | 正式内容切换、家庭真机连续使用、发布配置与运维验收 | 家庭试用与正式部署只允许 `release` 内容；完成访问与备份恢复验收 |
| M4 | AI 回顾与确认后的下周单卡调整，单独设计合同 | 本次仅文字预留；不选模型、不新增 AI 依赖、不在本次 OpenAPI 放实现路径 |

OpenAPI 的 `x-stage` 是交付标注，不是运行时功能开关。M1 部署可尚未注册 M2 路由；不得将技术性 404、空页面或伪造数据包装成可用历史/回顾。客户端按交付版本隐藏或明确显示尚未提供的入口；M2 上线后才连通真实数据。既有路径上的资源归属 404 与未实现路由不是同一产品状态。

首版一家庭、一台安卓手机，无账号注册、密码找回、登录页或设备账号体系。预置凭证由运维安全交付到手机；App 负责凭证安全存储，禁止在日志、截图、分析事件中输出。手机本地保存估算月龄、录入日、提醒配置；服务端只收到计划选择、时区和结构化打卡，不接收宝宝姓名、生日、照片、音视频。提醒由安卓本地安排。

## 2. 鉴权、编号与日期

### 2.1 鉴权和归属

所有 `/v1` 接口使用 `Authorization: Bearer <familyCredential>`。凭证是高熵不透明值，不预设 JWT。服务端根据凭证校验摘要定位有效 `families` 行；只保存安全摘要，不明文保存凭证。无凭证、无效或撤销返回 `401 UNAUTHORIZED`，附 `WWW-Authenticate: Bearer`。

客户端不传 `familyId`，服务端从凭证推导。读周、读汇总、打卡都将家庭条件纳入数据库查询。合法 UUID 不存在和属于别家一律返回相同的 `404 NOT_FOUND`，不得通过响应、错误详情或幂等重放泄露别家资源。对任务的归属检查必须在查询打卡幂等记录之前。建周没有已有目标资源，幂等查询直接限定已认证家庭。凭证撤销后，即使存在原成功请求也不能重放。

家庭、周、任务的资源编号以及业务 `requestId`、`operationId` 使用 UUID。`packageId`、`templateId`、`cardId`、`ageBand` 沿用内容合同字符串，不能改成 UUID。OpenAPI 的操作方法名 `operationId`（例如 `putCheckIn`）服务于代码生成，与打卡请求里的 UUID `operationId` 分开。

### 2.2 时间与时区

| 字段或概念 | 含义与存储 |
| --- | --- |
| `startDate`、`endDate`、Task.`date`、`asOfDate` | 有效 `YYYY-MM-DD` 业务日期，PostgreSQL `date`；不带 UTC 偏移，不经客户端 UTC 转换后截取日期 |
| `timezone` | IANA 时区名，例如 `Asia/Shanghai`；拒绝未知名称和 `+08:00` 这样的固定偏移 |
| `recordedAt` | 手机点选时的 UTC 时间，RFC 3339 且以 `Z` 结尾；离线时可早于上传很多天 |
| `syncedAt` | 服务端接受新操作的 UTC 时间；重放保留原值 |
| 数据库创建时间、操作接受时间 | PostgreSQL `timestamptz`；API 输出为 UTC `Z` |
| 今天 | 本次事务或一致性读取捕获的服务端瞬间，按对应周时区投影得到的日期；单次处理不跨午夜重复取值 |

首次成功建周时将请求 `timezone` 写入家庭，并复制到每周。M1～M3 固定家庭时区，后续请求必须与已固定名称一致；改变时区返回 `400 INVALID_REQUEST`，不静默迁移历史日期。有效 IANA 别名不自动视为另一个已存名称的同义值，客户端重复使用首次名称。首次建周失败不固定家庭时区。

此限制保证相邻周有唯一的“今天”，避免换时区后两个相邻周都声称覆盖当前日期。未来旅行/时区迁移需要另行设计，不纳入本次接口。尚无任何周时，`current` 直接返回 `200 {"week":null}`，不猜测服务器时区。

以日历加法计算七天和下一起始日，不按 `7 × 24` 小时推算，必须覆盖夏令时日。`recordedAt` 只记录点选时间，不用于判定任务日期、未来任务、修改顺序或覆盖优先级；手机时钟不可信。当前合同不以它和 `syncedAt` 的大小关系拒绝记录，界面也不得据此自动排序改记。

## 3. 内容导入、选择与历史隔离

### 3.1 导入业务校验

JSON Schema 校验之外，必须执行跨引用与业务校验；既有 [校验脚本](../../tools/validate_content.py)可作为内容侧检查入口，服务端仍须确保自己的导入边界满足规则：

- `schemaVersion` 必须为 `1`；`packageId`、版本与所有内容字段遵循原 Schema。所有档位编号、卡片编号、模板编号在各自集合内唯一。
- `ageBands` 必须完整声明以下七档，编号、月龄上下界及中文标签的语义一致，不得缺档、重复、重叠或新增第八档。没有模板的档位可以作为声明存在，但不可开始。
- 卡片的 `ageBands` 引用已声明档位；模板 `ageBand` 存在；模板恰有七个 `cardIds`，每个卡存在且支持模板档位。允许同一卡在七天内重复出现，每天仍生成独立 UUID 任务。
- 保留既有校验脚本的附加规则：`song`、`keywordsZh`、`english`、`numberPlay` 分别与 `song-rhythm`、`zh-words`、`daily-english`、`quantity` 领域成对出现；当前正式包编号沿用脚本限定的 `family-play-zh-cn`。固定七档检查是服务端额外业务约束，不能误认为现有脚本已经全部覆盖。
- 所有文本、链接、可选结构按原合同处理，不增设内容字段，不把卡片缩成标题摘要。记录规范化完整 JSON 内容的摘要，用于同版本冲突检查。
- 同 `packageId + contentVersion`、规范化 JSON 内容相同，重复导入返回已有结果且不产生副作用；对象键顺序与无意义 JSON 空白不算变化，数组顺序是内容的一部分。同版本不同内容一律拒绝，修改内容必须增大 `contentVersion`；新导入版本应高于本包已保存最大版本，回滚另走激活指针。
- 开发环境可用 `channel=demo`。家庭试用和正式环境禁止激活或新建使用 `demo` 的计划；试用数据从正式内容建立，开发数据库不得直接作为试用数据库。

| `ageBand` | 月龄范围 |
| --- | --- |
| `m00_02` | 0～2 月 |
| `m03_05` | 3～5 月 |
| `m06_08` | 6～8 月 |
| `m09_11` | 9～11 月 |
| `m12_17` | 12～17 月 |
| `m18_23` | 18～23 月 |
| `m24_35` | 24～35 月 |

### 3.2 激活与 options

每个 `packageId` 至多一个激活版本，允许多个包各自有激活版本。导入仅保存候选内容，不隐式激活；激活和回滚只可指向当前数据库中校验通过、符合环境渠道要求的版本。无效导入不写入半包，不改变激活指针。切换失败保留旧指针。

`GET /v1/content/options` 返回：

```json
{
  "packages": [{
    "packageId": "family-play-demo",
    "contentVersion": 1,
    "ageBands": [
      {"id":"m18_23","label":"18～23 月","minMonths":18,"maxMonths":23},
      {"id":"m24_35","label":"24～35 月","minMonths":24,"maxMonths":35}
    ],
    "weekTemplates": [
      {"id":"demo_week_m18","title":"演示｜18～23 月联调周","ageBand":"m18_23"},
      {"id":"demo_week_m24","title":"演示｜24～35 月切换周","ageBand":"m24_35"}
    ]
  }]
}
```

上例只适用于开发环境。返回每个包的完整可开始档位对象和模板摘要，不返回七天卡片或未有模板的声明档位。月龄到档位由客户端按固定七档匹配；找不到可开始模板时显示“该档内容待补”，不得自动降档或让家长按空按钮创建。`ageBand`、`packageId`、模板选择的关联在客户端和服务端都校验。

无任何有效激活包返回 `503 CONTENT_UNAVAILABLE`。已有可用包可正常返回；激活项损坏时必须告警并阻止其被选择，不提供损坏项。建周时选中一个有效活跃包但版本已经切换、或所选包不在可选集合，为 `409 CONTENT_STALE`；当前无可用内容或所选激活内容损坏为 `503 CONTENT_UNAVAILABLE`。客户端刷新选择后让家长重新确认，使用新的 `requestId`。

### 3.3 不可变历史

建周读取同一激活版本，保存周来源 `(packageId, contentVersion, templateId, ageBand)`，并把每个完整 card 写入 `tasks.card_snapshot JSONB`。API 的 `cardSnapshot` 直接 `$ref: ./content-package.schema.json#/$defs/card`，不复制一份缩水定义。`cardSnapshot.id = cardId`，卡片支持周档位。

导入、激活和回滚只影响未来新建周。已有当前周、预建周、历史周不重新排卡，快照不随源包修改；回滚也不撤销既有打卡或改写历史汇总。读取历史和提交历史打卡不依赖活跃指针，无活跃包时也应正常工作。M1～M3 不提供编辑、删除周或任务的公开接口。

## 4. 公共 JSON 结构与读取

完整字段约束、`additionalProperties`、枚举、响应和例子以 OpenAPI 为准。客户端不得依赖未声明字段，服务端拒绝可用请求中的未知字段，例如 `suggestionId`、`familyId` 或 `cardIds`。

| 对象 | 固定字段与说明 |
| --- | --- |
| `Week` | `{id,startDate,endDate,timezone,packageId,contentVersion,templateId,ageBand,tasks:[Task]}`；`ageBand` 为档位编号；tasks 恒为七项并按日期升序 |
| `Task` | `{id,date,dayNumber,cardId,cardSnapshot,checkIn,revision}`；`dayNumber=1..7`；`revision` 为非负整数，首次为 0 |
| `CheckIn` | `{status,feedback,recordedAt,syncedAt,operationId}`；`status=played|skipped`；反馈字段始终存在，可为 null |
| `CreateWeek` | `{requestId,startDate,timezone,packageId,contentVersion,templateId}`；全部必填，不接收 `suggestionId` |
| `PutCheckIn` | `{operationId,baseRevision,status,feedback?,recordedAt}`；feedback 缺省等于 null，其余必填 |

`Task.checkIn=null` 表示尚无服务端记录；`unrecorded` 与 `future` 是显示/汇总派生状态，不是 `CheckIn.status`。首次任务 `checkIn=null, revision=0`；成功的新打卡令 revision 加一。改记只能改变打卡和 revision，不能改变任务身份、日期和快照。

| 接口 | 响应与读取约定 |
| --- | --- |
| `POST /v1/weeks` | `201 {week:Week}`；幂等重放仍返回原始 201 与原创建时七任务，不包含之后的新打卡 |
| `GET /v1/weeks/current` | `200 {week:Week|null}`；按家庭今天找包含该日的周；空档、尚未建周、仅存在未来周均为 null |
| `GET /v1/weeks/{weekId}` | `200 {week:Week}`；属于本家庭且包含完整快照与当前已同步记录 |
| `PUT /v1/tasks/{taskId}/check-in` | `200 {task:Task}`；重放返回原操作接受时的 task，可能不是最新 revision |
| `GET /v1/weeks?limit=10&cursor=...` | M1提供接口用于排期发现、M2开放历史界面；`200 {weeks:[Week],nextCursor:string|null}`；空集合合法；默认10、范围1～50 |
| `GET /v1/weeks/{weekId}/summary` | M2，直接返回第 7 节规定的汇总对象，不再包一层 `summary` |

列表包含本家庭历史、当前及预建周，按 `(startDate DESC,id DESC)` 键集分页。初次请求记录一个成员边界，游标携带家庭、边界、末条排序键和完整性校验；后续新建周不进入该翻页序列。无效、篡改或其他家庭游标均 `400 INVALID_REQUEST`，不要透露其来源。`nextCursor=null` 表示末页，无 offset 和总条数承诺。周成员顺序稳定，页内任务是读取当时状态，不承诺多页共享数据库快照。客户端重新从首屏刷新以看到新周。

返回完整卡片是为了设计工具和客户端可直接渲染材料、步骤、四种家长台词、安全、来源以及实际存在的儿歌、数感、英文等可选字段。不得以当前内容包回填历史缺失字段；不展示不存在的模块。

## 5. 建周日期、幂等与事务

### 5.1 可开始日期

每周固定连续七个日历日，`endDate=startDate+6`，不要求周一开始；每家庭日期最多一个任务。把时区内今天记为 `today`：

- 没有任何既有周：`expectedStartDate=today`。
- 有既有周：取 `endDate` 最大的最近周，`expectedStartDate=max(today,last.endDate+1日)`。
- 只允许一个 `startDate>today` 的未来预建周；已有该周时新建请求为 `409 PLANNED_WEEK_EXISTS`。它开始当天就不再属于预建周，可创建下一周。
- 不支持任意跳到更远日期、不支持回填新建历史周、不允许重叠；断档后从今天重开，不补造空档任务。

例如今天 2026-11-11，首次为 11-11～11-17；可再建一周 11-18～11-24，随后不能继续堆积未来周。若最近一周结束于 11-01，则从 11-11 开始。若请求日期不等于应选日期，`409 START_DATE_CONFLICT`，详情含 `expectedStartDate` 和 `timezone`。即使请求日期不合法，只要命中原成功幂等记录仍重放原结果。

### 5.2 规范化与幂等键

建周唯一键为 `(familyId,requestId)`；打卡唯一键为 `(familyId,operationId)`，不能只按全局编号查缓存。打卡规范化载荷包含目标 `taskId`，因此同一家庭的同一操作编号用于另一任务会冲突；两个不同家庭的相同 UUID 相互隔离。

规范化规则：解析 JSON 后拒绝重复键、未知字段和非法类型；UUID 转为小写；日期使用严格公历日期文本；UTC 时间把同一瞬间的多余小数尾零归一，不能因格式变化变成新操作；feedback 省略补为 null；内容编号、状态和 IANA 名称区分大小写，不静默 trim 或替换。采用固定字段顺序的稳定 JSON 或等价规范编码比较，数组顺序保留；保存规范化请求及其摘要，不能只比较未验证的客户端摘要或忽略 `baseRevision`、`recordedAt`。

只对已经提交成功的写入建立永久幂等结果；401、404、静态 400、业务拒绝、503、500 均不占用成功幂等键。拒绝后的新确认仍应生成新编号。相同编号同规范化载荷返回原成功状态码及原响应体；相同编号异载荷返回 `409 IDEMPOTENCY_CONFLICT`。失败响应不会覆盖已有成功记录。M1～M3 不清理成功幂等记录，否则长期离线重试可能被误认为新操作。

业务幂等记录保存成功响应 JSONB、HTTP 状态码和接受时间，而不仅保存生成的周/任务编号。幂等重放不重新组装最新 Week/Task，不修改 `syncedAt`，不递增 revision。可用响应头 `Idempotency-Replayed: true` 标记，响应体不增加 `replayed` 字段。成功体没有通用 requestId 字段；所有响应头 `X-Request-Id` 是本次调用的新服务端追踪 UUID。错误体 `{error:{code,message,details?},requestId}` 的 requestId 同样是本次调用追踪值，与建周业务 UUID 分离。

### 5.3 建周原子步骤

1. 验证凭证，解析及规范化请求；开启数据库事务并锁住本家庭行，保证该家庭的并发建周串行。
2. 在家庭范围查建周幂等记录。命中同载荷直接返回已存结果；不同载荷返回幂等冲突。这里必须先于活跃包、日期、预建数量和模板等动态验证。
3. 对新请求确定事务内的今天，验证首次/固定时区。读取并锁定所选激活指针；检查活跃版本、渠道、内容完整性、模板和档位。已无可用内容用 503；选择过期用 409；活跃包无该模板或可开始档位用 `422 AGE_BAND_UNAVAILABLE`。
4. 先检查是否已有预建周；再检查请求七日范围是否重叠；再核对应选起始日。这样既有预建周优先 `PLANNED_WEEK_EXISTS`，其余已占用日期优先 `WEEK_OVERLAP`，最后为 `START_DATE_CONFLICT`。幂等冲突始终先于这些业务冲突。
5. 原子写入一个周、七个任务及完整 JSONB 快照、建周幂等请求与 `201 {week:Week}` 响应，首次成功时写家庭时区。初始 checkIn 为 null、revision 为 0。
6. 校验数据库唯一和跨表约束后提交，提交后才发送成功响应。任何一步失败全部回滚，不允许只有周没有七任务，或已建周但没有幂等记录。

激活切换使用与建周相容的指针行锁；读锁持有到快照和幂等结果提交，保证创建使用一个确定版本。CLI 不锁家庭行，以固定锁顺序避免死锁。并发唯一冲突应回到原幂等记录检查；同编号返回原结果，不同编号按事务内重新计算后的业务结果返回 409，禁止将约束错误泄露为裸 SQL。

不能只做“先 SELECT 再 INSERT”的应用检查。家庭行锁、七任务事务、数据库 `(family_id,date)` 唯一约束和延迟完整性校验共同保证无重叠；不以客户端按钮禁用代替数据库约束。

## 6. 打卡、修订与离线边界

### 6.1 状态和反馈

| `status` | 允许的 `feedback` |
| --- | --- |
| `played` | null、`want_again` |
| `skipped` | null、`family_busy`、`child_tired`、`time_unfit` |

feedback 省略等于 null；改记时不继承旧反馈。枚举全集内但配对不合法为 `422 INVALID_FEEDBACK`，未知枚举值、缺少必填字段、负数 revision、null status 为 `400 INVALID_REQUEST`。未来任务为 `422 FUTURE_TASK`，详情含 `asOfDate`。允许当天及历史补记、`played` 与 `skipped` 互改、单独修改反馈，不提供清空、DELETE 或把 `unrecorded` 写入的方式。

### 6.2 接受操作的顺序

1. 鉴权；按 `taskId + familyId` 查询目标归属，不存在或别家都 404。完成静态结构校验及规范化。
2. 锁目标任务，查询本家庭 `operationId` 的已提交结果。相同载荷立即原样重放，不再检查 baseRevision；异载荷 409。目标任务归属检查不能因为命中幂等记录而跳过。
3. 新操作才按周时区判断未来日期、校验反馈配对，然后检查 `baseRevision == tasks.revision`。不相等为 `409 REVISION_CONFLICT`，详情必须有完整 `currentTask`，不写入任何记录。
4. 在同一事务内新增或更新 `check_ins` 当前结果、将任务 revision 加一、保存 `check_in_operations` 规范化请求与 `200 {task:Task}` 原响应。接受时设置 syncedAt。新 operationId 即使与当前状态相同也算一次新操作，revision 加一。
5. 提交后响应。若发生 operationId 唯一竞争，回滚本次状态修改再检查已提交原记录，重放或报幂等冲突，不能遗留额外 revision。

示例：A 基于 revision 0 成功为 revision 1，但响应丢失；A 重试时应返回原 revision 1。若之后 B 已成功为 revision 2，再重试 A 仍返回原 revision 1，数据库保持 revision 2；不能因为 A 的 baseRevision 0 过期而报修订冲突，也不能把 A 再执行一次。新操作 C 带 baseRevision 1 才报 `REVISION_CONFLICT` 并返回 revision 2 的完整任务。

### 6.3 M2 客户端队列

离线缓存完整 Week/Task，打卡先事务写入 SQLite，再显示本地状态和“待同步”。同任务使用串行队列，只发送队首；不同任务可以独立同步。队列项的 operationId 在操作确认时生成，实际首次发送前以最近已确认服务端 revision 固化 baseRevision，发送后包括时间、反馈在内的载荷不得改变；超时重试必须原样使用同一编号及载荷。

本机后续改记独立保存为后续队列项，不篡改已发项。A 确认后才能将其返回 revision 用于尚未发送的 B。收到旧响应时仅确认对应队列项并更新服务端已确认基线，保留后续本地意图；不能按网络到达先后覆盖最新屏幕。若服务端返回的 revision 低于本地已确认 revision，不回退基线；需要刷新读取当前周。

`REVISION_CONFLICT` 时暂停该任务队列，展示“记录已变化”，显式重新 GET 所属周以取得当前完整任务，并请家长重新确认目标状态和反馈。确认后基于当前 revision 生成新 operationId 重发；未经确认不能自动替换 baseRevision、静默覆盖或把失败操作伪装同步成功。后续排队意图也须重新核对，不能越过冲突项继续写。

401 暂停同步并提示凭证问题；404 标记目标不可用；400/422 显示原因供修正；503、网络超时和 500 保留原队列并重试。应用恢复前台/网络恢复且应用打开时续传，不承诺后台永久运行或通知自动上传。基础汇总只反映已同步记录，存在本地待同步时明确提示；不把手机临时计数混入服务端 counts。

## 7. 基础汇总（M2）

响应结构为：

```text
{weekId,asOfDate,recordsVersion:string,
 counts:{played,skipped,unrecorded,future},
 days:[{taskId,date,status:played|skipped|unrecorded|future,feedback:null|enum}],
 review:null}
```

在一次一致性读取中捕获服务端瞬间，按周 timezone 得到 `asOfDate`，读取七任务及当前 check_in。按日期升序逐日分类：日期晚于 asOfDate 是 future；其余有 check_in 为 played/skipped，没有为 unrecorded。future 和 unrecorded 的 feedback 恒为 null；已记录日期沿用配对反馈。无论当前周、历史周还是未来预建周，days 恒为七项，四项 counts 必须与 days 一致且和为 7。未来一周可全为 future，历史未记录天数仍为 unrecorded，不自动变 skipped。

`recordsVersion` 是不透明字符串，可采用 `rv1:` 加规范化 `(weekId,asOfDate,按日期排序的七个 taskId/revision)` 的摘要。同一输入稳定，任何已接受打卡或改记令版本变化，跨周本地午夜即使无新打卡也必须变化；不能只用最后 syncedAt。API 不接受客户端用旧 recordsVersion 写入记录。客户端缓存回顾时同时检查该版本与日期，重新打开回顾须请求服务端核实。

读取周和汇总不得先后散读出互不匹配的 task revision 与 check_in；使用单 SQL 一致性查询或只读一致性事务。`review` 在 M2/M3 必须为 null，设计展示基础统计，不放可点击的 AI 生成按钮来假装 M4 已上线。

## 8. PostgreSQL 数据模型与约束

API 使用 camelCase，数据库使用 snake_case。以下是实施模型，不是已生成的迁移。UUID 资源主键由可信服务端生成；业务幂等 UUID 由客户端生成。表默认保留，历史外键使用 `RESTRICT`，不通过级联删除清理家庭历史。

| 表 | 主键与主要列 | 外键、唯一与约束 |
| --- | --- | --- |
| `families` | PK `id uuid`；`credential_hash`、`credential_revoked_at timestamptz null`、`timezone text null`、`created_at timestamptz` | 凭证摘要唯一；有成功周后 timezone 非空且 M1～M3 不变；该行是建周事务锁的入口 |
| `content_packages` | 复合 PK `(package_id text,content_version integer)`；`schema_version`、`channel`、`document jsonb`、`content_hash`、`validated_at`、`imported_at` | 版本 >=1，schema_version=1，channel 为 demo/release；document 完整且通过合同与业务校验；同 PK 内容不可变 |
| `active_content` | PK `package_id text`；`content_version integer`、`activated_at timestamptz` | 复合 FK `(package_id,content_version)` 指向 content_packages；每包仅一个指针；只有校验成功且环境允许的包可激活 |
| `week_plans` | PK `id uuid`；`family_id uuid`、`start_date date`、`end_date date`、`timezone text`、`package_id`、`content_version`、`template_id`、`age_band`、`created_at` | FK family_id；复合 FK 包版本；UNIQUE `(family_id,start_date)`、`(id,family_id)`；CHECK end_date=start_date+6；age_band 限固定七档；日期不可变 |
| `tasks` | PK `id uuid`；`week_id uuid`、`family_id uuid`、`date date`、`day_number integer`、`card_id text`、`card_snapshot jsonb`、`revision integer default 0` | 复合 FK `(week_id,family_id)` 到 week_plans；UNIQUE `(family_id,date)`、`(week_id,day_number)`、`(week_id,date)`、`(id,family_id)`；day_number 1～7、revision>=0；快照 object 且 id=card_id |
| `check_ins` | PK `task_id uuid`；`family_id uuid`、`status text`、`feedback text null`、`recorded_at timestamptz`、`synced_at timestamptz`、`operation_id uuid` | 复合 FK `(task_id,family_id)` 到 tasks；FK `(family_id,operation_id)` 到操作表；status 仅 played/skipped；显式 CHECK 反馈配对，注意 SQL NULL 三值逻辑；每任务仅一当前行 |
| `check_in_operations` | 复合 PK `(family_id uuid,operation_id uuid)`；`task_id uuid`、`base_revision integer`、`result_revision integer`、`normalized_request jsonb`、`request_hash`、`response_status integer`、`response_body jsonb`、`accepted_at timestamptz` | FK family_id；复合 FK `(task_id,family_id)` 到 tasks；成功状态固定 200；UNIQUE `(task_id,result_revision)`、`(family_id,operation_id,task_id)`；请求和原响应不可变 |
| `week_creation_requests` | 复合 PK `(family_id uuid,request_id uuid)`；`week_id uuid`、`normalized_request jsonb`、`request_hash`、`response_status integer`、`response_body jsonb`、`accepted_at timestamptz` | FK family_id；复合 FK `(week_id,family_id)` 到 week_plans；UNIQUE week_id；成功状态固定 201；幂等记录与周同事务写入且不可变 |

`check_ins` 引用的 operation 必须属于同一任务：实施时使用复合 FK `(family_id,operation_id,task_id)` 对应操作表唯一键，不能只验证编号存在。操作表不引用 check_ins，以避免循环依赖；在事务中先更新 task、插入 operation，再新增/更新 check_in，原响应根据同事务的新状态生成。所有主外键非空，只有明确标记 null 的字段可空。

模板、卡片位于 content_packages.document 内，不能用普通 FK 指到 JSON 数组。服务端导入验证引用，建周再次从已验证不可变文档解析；任务快照仍独立保存。使用数据库 CHECK 验证 JSONB 是对象、含必需身份值，完整 JSON Schema 与跨字段关系由入口校验；禁止其他写入口绕过。

必须增加事务提交时的完整性保证（延迟约束触发器或等价数据库机制）：

- 每个周恰有七任务，day_number 恰为 1～7，`task.date=week.start_date+day_number-1`，family_id 与周一致，时区与家庭固定值一致。
- 新周七日期各唯一，配合 `(family_id,date)` 直接阻止重叠。预建数量和应选起始日通过同家庭行锁下的查询与写入保证；不要添加依赖 `CURRENT_DATE` 的静态 CHECK 来表达会随日期变化的预建数量。
- revision 0 对应没有 check_ins；revision>0 对应一条当前 check_in，其 operation.result_revision 等于 tasks.revision，操作目标与家庭一致。任务与操作结果更新一起提交。
- 周、任务、快照及成功幂等记录创建后不可任意改写；允许的更新只有打卡事务修改 task.revision 和 check_ins，以及合法的激活指针切换。

上述约束不要求新加数据库扩展。若实现另加区间排斥约束可作为加固，但不能取消七任务完整性与日期唯一约束。为查询建立 `week_plans(family_id,start_date DESC,id DESC)`、`week_plans(family_id,end_date DESC)` 索引；任务按 week_id/date 读取；操作以复合主键查重。建周不引用激活指针作为历史 FK，避免后续回滚导致历史行无效。

## 9. 错误合同与界面行为

统一错误体如下，所有错误也附本次 `X-Request-Id`，不输出堆栈、SQL、凭证或别家编号：

```json
{
  "error": {
    "code": "START_DATE_CONFLICT",
    "message": "请使用下一可用起始日",
    "details": {"expectedStartDate":"2026-11-18","timezone":"Asia/Shanghai"}
  },
  "requestId": "50000000-0000-4000-8000-000000000005"
}
```

| HTTP / code | 必需行为与详情 |
| --- | --- |
| 400 `INVALID_REQUEST` | JSON、路径 UUID、字段、类型、日期、时区、游标非法；可给 details.fields；固定家庭时区不符也用此码 |
| 401 `UNAUTHORIZED` | 不能重放、读取或写入；提示家庭凭证失效 |
| 404 `NOT_FOUND` | 资源不存在与别家资源相同响应，无归属详情 |
| 409 `CONTENT_STALE` | 刷新 options，再由家长确认；已知新激活版本可给 details.activeContentVersion |
| 409 `WEEK_OVERLAP` | 日期已占用；details.existingWeekId 仅可指本家庭 |
| 409 `START_DATE_CONFLICT` | details.expectedStartDate、timezone；重新展示日期等待确认 |
| 409 `IDEMPOTENCY_CONFLICT` | 同业务编号异规范化载荷，不静默换键重试 |
| 409 `REVISION_CONFLICT` | details.currentTask 必须为完整 Task；重新读取并确认，不偷偷覆盖 |
| 409 `PLANNED_WEEK_EXISTS` | details.existingWeekId；打开已预建周，不继续创建 |
| 422 `FUTURE_TASK` | details.asOfDate；未来日期只可看卡，不可打卡 |
| 422 `INVALID_FEEDBACK` | 状态与枚举内反馈不配对；保留本地意图供修正 |
| 422 `AGE_BAND_UNAVAILABLE` | 活跃包中模板缺失或档位不可开始；提示该档待补，不降档 |
| 503 `CONTENT_UNAVAILABLE` | 无可用内容、内容损坏或渠道被禁止；历史读取、历史打卡不因此失败 |
| 500 `INTERNAL_ERROR` | 未分类内部故障；事务不部分成功；若提交成功但响应丢失，以原编号重试可重放 |

所有家庭数据响应 `Cache-Control: no-store`。无公开内容列表供未认证用户访问。HTTP 传输与网关也应把应用错误转成统一结构；尚未实现的 M2 路由不作为正式错误业务流程依赖。客户端按 code 判断，message 为中文可读说明。

## 11. M4 独立预留

AI 仅在后续阶段单独定义请求、响应、持久化与超时行为。本次 OpenAPI 不放 `ai-review`、suggestion 应用路由或 `suggestionId` 请求字段；M2/M3 汇总的 review 固定为 null。

后续建议只基于已经同步的任务/修订、结构化反馈和基础计数，以周内相对天数替代家庭身份及精确生活时间。需要记录依据的 recordsVersion，跨日或改记后旧建议不得冒充当前依据。数据不足、失败或无建议时基础回顾照常可用。任何替换须符合有效包、目标档位和下周边界，经家长确认仅替换下周一天；不修改已开始周和历史。模型选择、供应商、密钥及依赖均留待 M4 决定。

| 当前周 | 未建、空档、仅未来周、覆盖今天 | 前三者 200 week:null；最后完整唯一周 |
| 并发建周 | 相同 requestId 同载荷同时提交 | 恰一个周与七任务，一份幂等结果，两次同 201 内容 |
| 并发建周 | 不同 requestId 抢同日起建；中间写任务失败 | 只允许一个计划，另一请求 409；失败不留半周或孤儿幂等行 |
| 幂等建周 | 成功后跨日、切包、回滚再原样重试 | 返回原始创建响应，不重新做动态验证或换快照 |
| 幂等冲突 | 同 requestId 改日期/版本；同 operationId 改任务/反馈/baseRevision | 本家庭内均 409 IDEMPOTENCY_CONFLICT，不修改原结果 |
| 打卡 | 首次 baseRevision 0；历史补记；played/skipped 互改 | 成功，完整 task 返回，revision 每新操作加一 |
| 反馈 | 缺省反馈与显式 null 的同编号请求 | 规范化相同，原结果重放；改记不继承旧反馈 |
| 反馈 | played+family_busy；skipped+want_again；status=unrecorded | 前两者 422 INVALID_FEEDBACK，后者 400 |
| 未来 | 篡改 recordedAt 为过去、时钟超前，给未来任务打卡 | 仍按服务端周时区今天判为 422 FUTURE_TASK |
| 修订 | A 成功丢响应，B 已为 revision 2，再重试 A | 返回 A 原 revision 1；数据库和当前读取保持 revision 2 |
| 修订 | 新 operationId 带旧 baseRevision | 409，details.currentTask 完整；客户端重取、重新确认再新编号提交 |
| 离线 | 同任务 A/B 排队、重开、乱序到达旧响应 | 只发送队首、固化重试载荷；保留后续本地意图、不回退新状态 |
| 历史 | 激活改台词的新版本、回滚、取消当前激活 | 新周依创建时内容；旧周快照与打卡不变，仍可读取和补记 |
| 列表 | 多页、并发新建、错误/别家游标 | 无重复漏翻已有成员，新周刷新首屏可见，非法游标 400 |
| 汇总 | played/skipped/未记录/未来混合；全未记；全未来 | days 七项，sum=7，反馈配对，review=null |
| 汇总 | 无新打卡跨周时区午夜；修改同状态反馈 | recordsVersion 均变化；同日同修订重复读取稳定 |
| 阶段 | M1 页面；M2 离线待同步 | M1 不伪装可用历史/回顾；M2 明确本地与已同步边界 |
| 运维 | 激活与建周并发；切换失败；备份后恢复 | 创建用单一版本，失败留旧指针；恢复后快照和幂等结果一致 |

最小持久记录仅覆盖家庭凭证摘要、固定时区、内容版本与激活、周与快照、当前打卡及其必要幂等请求/响应。不扩展儿童个人资料、自由文本日记、媒体或事件追踪。check_in_operations 保存的是可靠重试与修订依据，不据此承诺对家长开放完整编辑历史或行为分析功能。
