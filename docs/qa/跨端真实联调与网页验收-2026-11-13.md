# BabyPlan 跨端真实联调与网页验收

日期：2026-11-13～14（Asia/Shanghai）

本报告记录家长网页、真实 Fastify HTTP 服务和隔离 PostgreSQL 数据库之间的联调结果。测试使用虚构账号、家庭和开发内容夹具，不修改候选内容，也不冒充人工审读。

## 结论

本轮自动化范围内的跨端事实闭环全部通过：

- 创建两个账号与两个独立家庭。
- 用邀请令牌把第二位家长加入目标家庭。
- 为今天起七天生成安排，三端读取同一天的同一份计划。
- 第一位家长写入参与记录，第二位家长读回相同事实。
- 用另一家庭的孩子 UUID 请求时返回 404。
- 家长网页通过 HttpOnly Cookie 登录，并读回手机端同一活动和参与状态。
- 网页缺少 CSRF 头时写请求返回 403；携带 CSRF 后成功保存，手机 API 再读回更新。
- 手机与网页双向读取成长正文、卧位身长和照片；删除和恢复小记、上传失败后仅重试照片、下载同日期 ZIP。
- 月龄跨档、家庭材料和语言筛选、未来安排重排；家庭快照分页一致，撤权后旧页不可读。
- 活动撤回后详情、打印和新导出隐去原步骤；旧导出链接失效。
- 网页用真实键盘焦点和 Enter 切换导航。
- 360px 宽、200% 根字号下，设置页和陪伴安排页均无页面级横向溢出。
- Chromium 运行期间没有 JavaScript 页面异常。

最终复跑结果：

- API 默认真实数据库用例 6 个；另有真实 HTTP/Chromium 以及隔离备份恢复各 1 个。
- 家长网页测试：26/26 通过。
- 跨端 Chromium 主流程：1 个集成测试通过，包含报告中的 28 项逐段检查。
- API `typecheck` 与 Build 通过。
- 网页及服务器脚本语法检查通过。
- 夹具清理后，测试用户、家庭和内容修订残留数均为 0。

## 发现并修复的问题

1. 浏览器默认 `fetch` 丢失 `Window` 接收者，网页报 `Illegal invocation`。默认调用已绑定 `globalThis`，并在 `apps/web/test/helpers.test.mjs` 保留回归测试。
2. 中文日期 helper 把布尔 `weekday: true` 直接传给 `Intl.DateTimeFormat`，抛 `RangeError` 并中断今日计划渲染。现在会把 `true` 规范成 `'long'`，并有日期回归测试。
3. 参与记录修订号从 PostgreSQL 返回字符串，服务端用严格比较对照数字时，相同修订号也返回 409。已在参与记录读写中先数值化，并保留“已有记录二次更新、手机再读回”的跨端回归。
4. 360px 和 200% 根字号下，header 用户菜单保持单行导致页面宽度 406px。已让用户区换行及收缩，最终两个主要页面均无页面级横向溢出。
5. 补缺回归时发现家庭设置表单在 360px 和 200% 字号下有 10px 固有宽度溢出，已调整表单收缩规则并重新通过真实 Chromium 检查。
6. 网页家庭导出的下载链接原先使用新窗口，Windows 自动化环境里下载事件可能不出现，建议文件名还会受浏览器默认命名影响。现在改为同页下载并固定使用 `babyplan-<任务ID>.zip`，浏览器下载事件、同源签名响应和 ZIP 内容分别核验。

后续修复了照片链接被浏览器安全策略拦截、网络传输失败重复提交、以及北京时间按天导出少一天的问题。现在上传、预览和下载沿用家长网页的服务入口；联调检查下载点击触发预期的 ZIP 文件名，并通过同源签名入口读取 ZIP，确认其中包含当天实际正文和照片。当前 Windows 自动化环境会让 Playwright 的下载事件立即进入 canceled，因此没有把磁盘落盘写成已通过。内容工作台的角色和审核发布由单独的数据库工作流用例覆盖。
