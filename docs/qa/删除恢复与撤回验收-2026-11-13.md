| 实际走过的路径 | 结果 |
| --- | --- |
| 把数据库和照片做成同一时间点的备份，然后永久删除一个家庭、一条小记和另一条小记的照片 | 读取立即受限；独立台账留下三条记录，源库异步清理完成 |

| 活动已撤回，再用之前的 ZIP 下载链接，或重新申请计划导出 | 旧链接失效；新 ZIP 仍保留记录但只显示停止推荐提示 |
| 分页期间另一位家长新增记录，或删除记录/移除成员 | 同批分页读取同一时点；新增进入后续变更；删除使旧分页失效；成员移除后旧令牌无法使用 |

一次实测：PostgreSQL 9.5.4 新库应用迁移 0001–0008，恢复耗时 17.19 秒；完成时备份距离生成 21.43 秒。详见本机 `.work/bp_deletion_drill_7b878f6763f0/evidence.json`。这组小样本不能用来预测生产家庭的恢复耗时或数据丢失窗口。生产目标是 24 小时内可恢复的数据点、4 小时内恢复服务，尚未在真实目标机器与磁盘验证。

断网时，已经知道的撤回继续生效；还未收到的撤回要等重新联网。手机会在打开玩法或同步前先核对。Flutter 使用持久 SQLite 验证离线重开和草稿保留，网页与接口使用真实 Chromium 和 PostgreSQL。真机通知、系统选图、双机切网和覆盖升级另行验收。

演练使用 `services/api/test/deletion_restore.test.ts`，需要隔离 PostgreSQL 管理员连接、服务端构建和 PowerShell 7。可以通过 `scripts/verify.ps1 -RunRestoreDrill -WriteReport` 执行；管理员 URL 从当前进程的 `BABYPLAN_DELETION_DRILL_ADMIN_URL` 读取，不写入报告。台账位置与恢复后重新登录、重新邀请的说明见 [私有部署与备份恢复](../ops/私有部署与备份恢复.md)。
