# BabyPlan 私有部署与备份恢复

2026-11-13 · Windows 私有部署手册

本手册面向一位维护者和自己的家人。它默认只有一台 Windows 主机、一个私人域名、一个 PostgreSQL 数据库和一个私有媒体目录。外部部署、TLS 证书、签名密钥和真实家庭验收不在脚本内自动完成。

## 1. 目标与边界

- 默认只监听 `127.0.0.1`；只有显式使用首次安装向导的 `-LanAccess` 时才允许受信任局域网访问。
- 家长网页由 Caddy 提供 HTTPS，并把同源 `/v2` 请求代理给 API。
- PostgreSQL、媒体文件、日志和备份目录相互分离。
- 永久删除台账与备份分开保存。恢复时须使用同一部署的最新台账。
- 账号恢复投递目录独立于媒体、备份和恢复目录，仅供维护者账户读取。
- 正常备份与恢复产物目录 `data/backups`、`data/restores` 分开；恢复目录不能覆盖正式媒体。
- 备份默认要求先停止 API，保证数据库 dump 与媒体快照来自同一维护窗口。
- 恢复默认创建新数据库和新媒体目录，不覆盖现有数据。
- 数据库升级只向前迁移。回退通过恢复旧备份到新数据库并切换配置完成，不执行逆向 SQL。
- 目标 RPO 为 24 小时、RTO 为 4 小时，但这两个指标尚未在真实生产服务器验证。

## 2. 前置条件

- Windows PowerShell 7。
- Node.js `24.x`。
- 真实家庭服务请使用 [官方仍在支持的 PostgreSQL 版本](https://www.postgresql.org/support/versioning/)，并在相同版本演练迁移和恢复。本机 `9.5.4` 只用于隔离兼容验证。
- Flutter `3.47` 或当前项目锁定版本，仅在构建 APK 的机器需要。
- Caddy 或其他能终止 TLS 的反向代理。
- 私钥、数据库口令和一次性引导凭证不得进入仓库、聊天记录或普通日志。

以下命令均从仓库根目录执行。实际目录可以改名，但必须保持在同一受控根目录内。

## 3. 普通家长的最短启动路径

不需要手工编辑环境文件。准备好 Windows PowerShell 7、Node.js 24 和 PostgreSQL 后，在项目目录运行：

```powershell
.\scripts\ops\Install-BabyPlan.ps1 -LanAccess
```

向导会依次询问数据库管理员连接、管理员邮箱、称呼、家庭名称、宝宝小名、月龄和登录口令。数据库管理员 URL 与初始口令均隐藏输入；成功后：

- 创建隔离环境、随机数据库口令、专用数据库角色和数据库。
- 安装依赖、构建、迁移，创建首个部署管理员和家庭。
- 导入并启用 `content/candidate/babyplan-18-23-v2.json`，标记为 `development` 测试内容。
- 启动 API 与家长网页，并检查健康状态。
- 把初始账号、家庭标识和 API 地址写入私有目录的 `config/initial-owner.env`，不会打印口令。

默认私有目录是 `.work/private`，也可以把 `-Destination` 指向仓库外目录。如果目标位于仓库内却不在 `.work` 下，脚本会拒绝运行。此向导只用于隔离的 `development` 试用；若目标目录已有正式配置，向导会拒绝写入。用正式资料时建立独立部署。

同一 Wi-Fi 下的开发 APK 连接地址由向导输出。也可以手工查询当前默认网卡 IPv4：

```powershell
$route = Get-NetRoute -DestinationPrefix '0.0.0.0/0' |
  Sort-Object RouteMetric, InterfaceMetric |
  Select-Object -First 1
Get-NetIPAddress -InterfaceIndex $route.InterfaceIndex -AddressFamily IPv4 |
  Select-Object InterfaceAlias, IPAddress
```

手机应连接形如 `http://192.168.1.20:4318` 的 API 地址，并确保手机与 Windows 主机处于同一 Wi-Fi、客户端隔离未开启、Windows 防火墙已按实际网络放行 `4318`。不要填写 `127.0.0.1`，它在手机上指向手机自身。局域网 HTTP 只供开发 APK 试用；正式 APK 按客户端配置会拒绝非 HTTPS 地址。

## 4. 手工建立和维护环境

```powershell
$privateRoot = 'E:\BabyPlan-private'

.\scripts\ops\Initialize-BabyPlanEnvironment.ps1 `
  -Destination $privateRoot `
  -DatabaseHost '127.0.0.1' `
  -DatabasePort 5432 `
  -DatabaseName 'babyplan' `
  -DatabaseUser 'babyplan' `
  -ApiPort 4318 `
  -WebPort 4174 `
  -PublicBaseUrl 'http://127.0.0.1:4174'

$envFile = Join-Path $privateRoot 'config\babyplan.env'
```

脚本生成随机数据库口令，并创建：

```text
config/babyplan.env
config/runtime.json
data/media/
data/backups/
data/restores/
data/recovery-outbox/
data/deletion-journal/
logs/
runtime/
```

本机试用可以使用默认 HTTP 地址。通过 Caddy 对外开放时，`-PublicBaseUrl` 必须改为最终 HTTPS 域名，例如 `https://babyplan.example.com`；它用于生成短期媒体链接。已有环境文件永远不会被覆盖，`-Force` 只允许补齐不存在的目录。

脚本不会连接或修改系统中已经存在的 PostgreSQL。Windows ACL 不能进一步收紧时，脚本会警告；此时必须人工确认父目录只允许部署账户读取。

`MEDIA_ROOT` 是 API 实际读取媒体的路径，`MEDIA_STORAGE_PATH` 是运维脚本读取的同一路径。生成脚本会把二者写成同一目录，备份脚本发现二者不一致时失败。不要只修改其中一个。

`RECOVERY_OUTBOX_ROOT` 是账号恢复链接的私有管理员投递目录，必须与媒体、备份和恢复目录完全分离。初始化脚本会创建 `data/recovery-outbox/`，部署脚本会验证生产配置和路径边界。不要把它放进网页静态目录、媒体目录或可下载备份中；该目录只允许维护者账户读取。

`DELETION_JOURNAL_ROOT` 默认是 `data/deletion-journal/`。保留 `journal.json` 和全部事件文件；它们只有删除类型、时间和必要标识。实际部署将台账放到独立受保护磁盘，或保持独立副本持续更新。台账不可放在媒体、备份、恢复或网页目录内。配置旧环境升级到 0008 后，先启动 API 一次初始化台账并补做清理，再停服生成新版备份。

数据库管理员连接只放在当前进程环境中，使用带隐藏输入的提示，完成后立即移除：

```powershell
$env:BABYPLAN_ADMIN_DATABASE_URL = Read-Host '管理员 PostgreSQL URL' -MaskInput
try {
  .\scripts\ops\Initialize-BabyPlanDatabase.ps1 `
    -EnvironmentFile $envFile
} finally {
  Remove-Item Env:BABYPLAN_ADMIN_DATABASE_URL -ErrorAction SilentlyContinue
}
```

已有角色默认不改口令。只有确认需要把角色口令更新为环境文件中的新值时才使用 `-RotatePassword`。脚本不会输出管理员 URL 或应用数据库口令。

## 5. 构建、迁移和内容

先验证候选内容；正式内容还必须完成人工审读与家庭试玩证据：

```powershell
python -I tools/validate_v2_content.py content/candidate/babyplan-18-23-v2.json
```

构建并迁移：

```powershell
.\scripts\ops\Deploy-BabyPlan.ps1 -EnvironmentFile $envFile
```

部署前会拒绝缺失或不一致的 `MEDIA_ROOT`、`MEDIA_STORAGE_PATH`，拒绝不存在的媒体目录和无凭证 `PUBLIC_BASE_URL`，避免服务启动后把照片写入另一处默认目录或签出错误下载地址。

导入经允许的内容包：

```powershell
.\scripts\ops\Deploy-BabyPlan.ps1 `
  -EnvironmentFile $envFile `
  -SkipInstall `
  -ContentPackage 'D:\content\approved-package.json' `
  -ContentEnvironment private_trial
```

导入与发布分开。带审核权限的账号在家长网页打开“内容工作台”，完成审读、选择固定的修订及证据后，由发布者选择 `private_trial` 或 `public`。工作台会按环境核验发布门禁。`-PublishReleaseId` 只用于开发环境，不能绕开工作台的审读与证据检查。正式私有服务初始化后默认只读取 `private_trial`。

## 6. 启动、健康检查和停止

```powershell
.\scripts\ops\Start-BabyPlan.ps1 -EnvironmentFile $envFile

# 或分别启动：
.\scripts\ops\Start-BabyPlanApi.ps1 -EnvironmentFile $envFile
.\scripts\ops\Start-BabyPlanWeb.ps1 -EnvironmentFile $envFile

Invoke-RestMethod 'http://127.0.0.1:4318/health/ready'
Invoke-WebRequest 'http://127.0.0.1:4174/' -UseBasicParsing
```

进程以隐藏窗口启动，PID 写入 `runtime/api.pid` 或 `runtime/web.pid`，标准输出和错误按运行批次分别写入 `logs/api-<时间>-<随机标识>.stdout.log`、`logs/api-<时间>-<随机标识>.stderr.log` 及对应网页日志。每次重启不会覆盖上一批日志。停止顺序为网页、API：

```powershell
.\scripts\ops\Stop-BabyPlan.ps1 -EnvironmentFile $envFile

# 或分别停止：
.\scripts\ops\Stop-BabyPlanWeb.ps1 -EnvironmentFile $envFile
.\scripts\ops\Stop-BabyPlanApi.ps1 -EnvironmentFile $envFile
```

停止脚本只终止命令行明确指向本项目 `dist/server.js` 或 `server.mjs` 的 Node 进程。PID 不匹配时拒绝操作。

## 7. HTTPS 入口

复制 [Caddyfile.example](../../ops/Caddyfile.example) 到私有部署配置目录，设置域名环境变量后启动 Caddy：

```powershell
$env:BABYPLAN_DOMAIN = 'babyplan.example.com'
caddy run --config 'E:\BabyPlan-private\Caddyfile'
```

浏览器只访问 Caddy 的 HTTPS 域名；API 和网页端口继续绑定 `127.0.0.1`。正式使用前确认：

- 域名 DNS 指向正确主机。
- 443 与 80 端口可从需要的网络访问，4318 和 4174 不对公网开放。
- Cookie 在 HTTPS 下为 Secure、HttpOnly、SameSite。
- Caddy 自签或公共证书由实际浏览器验证，不把配置示例当作证书已签发。

## 8. 一致性备份

备份必须安排一个维护窗口：

```powershell
.\scripts\ops\Stop-BabyPlanWeb.ps1 -EnvironmentFile $envFile
.\scripts\ops\Stop-BabyPlanApi.ps1 -EnvironmentFile $envFile

$backup = .\scripts\ops\Backup-BabyPlan.ps1 -EnvironmentFile $envFile

.\scripts\ops\Start-BabyPlanApi.ps1 -EnvironmentFile $envFile
.\scripts\ops\Start-BabyPlanWeb.ps1 -EnvironmentFile $envFile
```

备份目录包含：

```text
database.dump
media/
manifest.json
```

`manifest.json` 记录数据库摘要、迁移、媒体树摘要、一致性及删除台账的部署标识。脚本校验数据库归档和媒体复制前后的摘要；媒体目录存在链接时失败。先等待永久删除任务完成；未完成清理的环境不能生成可上线恢复的备份。

API 在线时脚本默认拒绝备份。紧急情况可使用 `-AllowOnlineBackup` 采集材料，但标记为 `online_unverified` 的备份不能用正常恢复流程上线。恢复要求停服校验过的 v2 备份和最新独立台账。

建议保留 30 天并至少把一份备份放到另一块受控磁盘。不要自动删除最后一份已验证备份。Windows 任务计划只能用于触发维护窗口脚本；若每天都要备份，就把“停止服务、备份、服务恢复”做成经过审核的单一维护任务。

已经验证服务和维护脚本路径后，可以用一个命令完成受控维护窗口：

```powershell
.\scripts\ops\Invoke-BabyPlanMaintenanceBackup.ps1 `
  -EnvironmentFile $envFile
```

它会记录调用前 API 与网页是否在线，停止网页和 API，生成一致性备份，然后在 `finally` 中只恢复原先运行的服务。备份失败时同样会尝试恢复服务，并把原始失败抛回任务计划记录。

## 9. 恢复与验证

普通应用角色没有建库权限。恢复管理员连接只在当前 PowerShell 进程中读取，不进入环境文件、命令参数或日志：

```powershell
$env:BABYPLAN_RESTORE_ADMIN_DATABASE_URL = Read-Host '恢复管理员 PostgreSQL URL' -MaskInput
```

管理员连接必须与应用 `DATABASE_URL` 指向同一 PostgreSQL 主机和端口，并具备建库、删除临时库及调整对象所有权的权限；实际应使用受控的部署 DBA 或超级用户。恢复脚本要求显式确认，并默认创建新数据库：

```powershell
$restore = .\scripts\ops\Restore-BabyPlan.ps1 `
  -EnvironmentFile $envFile `
  -BackupPath $backup.path `
  -DeletionJournalRoot 'E:\BabyPlan-journal' `
  -ConfirmRestore
```

完成后立即清理进程变量：

```powershell
Remove-Item Env:BABYPLAN_RESTORE_ADMIN_DATABASE_URL -ErrorAction SilentlyContinue
```

将示例中的台账目录换为同一部署的最新台账。若配置文件已指向正确目录，可以省略 `-DeletionJournalRoot`。源 API 和网页在恢复期间应保持停止。

恢复前会校验：

- 停服版 v2 清单、数据库与媒体摘要、删除台账部署标识及台账覆盖情况。旧 v1 备份不能直接作为恢复上线环境；在仍有可信源库时先升级源库并重新备份。
- 目标数据库不存在，媒体恢复目录不存在。
- 目标数据库名使用受限字符集。
- 恢复管理员与应用数据库位于同一主机和端口。

恢复先校验数据库与原始媒体，再把独立台账中的永久删除重放到新库和新媒体目录。只有重放完成才写恢复环境。恢复时旧会话、邀请、签名链接与同步游标失效，原陪伴者须由管理员重新邀请。报告记录重放条数、恢复耗时和备份年龄，并生成：

```text
restored-<database>.env
restore-<database>.json
media-<database>/
recovery-<database>/
```

`recovery-<database>/` 是恢复环境专用的空账号恢复投递目录，脚本会把生成环境文件的 `RECOVERY_OUTBOX_ROOT` 改到这里，避免试启动时写入原环境。数据库与私有媒体备份不包含正在投递的恢复文件；恢复后如有尚未完成的账号恢复请求，应作废并重新发起。

先使用生成的环境文件在备用端口启动并验收，再切换正式配置。不要直接覆盖现有数据库。确认无误后，再由维护者决定停用旧库；永久删除不属于恢复脚本的自动步骤。

自动演练：

```powershell
$evidence = .\scripts\ops\Test-BabyPlanBackupRestore.ps1 `
  -EnvironmentFile $envFile `
  -ArtifactRoot .work\ops-backup-restore-drill-<timestamp>
```

演练也会从当前进程读取 `BABYPLAN_RESTORE_ADMIN_DATABASE_URL`。它比较新备份的表计数和媒体摘要，默认删除临时恢复数据库并保留证据。另有隔离集群专用的 [旧备份删除重放验收](../qa/删除恢复与撤回验收-2026-11-13.md)。这两个验证都不能替代另一台真实服务器的恢复。

## 10. 升级与回退

升级前必须完成一次备份并记录：

- Git 说明或源码版本标识。
- 当前 API 构建时间和内容版本。
- PostgreSQL 版本、迁移列表、备份路径与摘要。
- APK 版本、签名证书指纹和 SHA-256。
- 当前健康检查结果和已知故障。

升级流程：

1. 安排停机窗口，停止网页和 API。
2. 运行一致性备份。
3. 拉取已审阅的源码或安装包，执行 `npm ci`、类型检查、测试和构建。
4. 运行 `Deploy-BabyPlan.ps1` 应用向前迁移。
5. 启动 API，读取 `/health/ready`；启动网页，检查 `/` 和真实登录路径。
6. 在第二台设备或第二账号上确认计划、参与记录和成长记录可读。
7. 保留上一版构建和备份，观察稳定后再清理旧产物。

迁移失败时不要手工修改迁移记录。恢复回退流程：

1. 停止服务并保留失败日志，不覆盖故障现场。
2. 把升级前备份恢复到新的数据库和媒体目录。
3. 用恢复环境文件在备用端口启动支持现有迁移和删除台账的服务；不直接启动不支持 0008 的旧构建。
4. 验证迁移、数据计数、登录和双端读取。
5. 切换到已验证的恢复环境；保留故障数据库供定位，不直接删除。

## 11. 隐私和运维规则

- 不把 `DATABASE_URL`、会话令牌、邀请令牌、照片正文或真实儿童资料写进工单和日志。
- 核对 API 日志的认证与 Cookie 脱敏配置；反向代理不得记录请求正文或认证头。
- 备份、媒体、环境文件和恢复环境文件都按私人数据保管。
- 日志与数据库容量、磁盘余量、健康检查和备份结果需要人工巡检。
- 撤回收藏、家庭删除或永久删除涉及异步媒体清理时，必须同时核对数据库墓碑和媒体对象；没有清理证据不得假报完成。

## 12. 当前未验证

- 本仓库尚未具备真实公网域名、TLS 证书、生产 PostgreSQL 和独立媒体存储。
- 未验证真实家庭所在 Wi-Fi 的客户端隔离、Windows 防火墙规则、手机到主机的双向连通和正式 APK 的 HTTPS 连接。
- 没有生产服务器的 RPO/RTO 实测结果、磁盘故障演练或密钥托管记录。
- Windows ACL 收紧在当前开发机受 `SeSecurityPrivilege` 限制；脚本会警告并继续，实际部署必须人工确认目录权限。
- 本手册的备份恢复只验证了同一开发机内的新数据库恢复。独立台账副本必须持续更新；恢复脚本不能发现主机整体丢失后，拿到的台账副本是否缺少备份之后的最新事件。
- 未修改本机既有系统 PostgreSQL；演练只使用隔离开发集群和新建临时数据库。
